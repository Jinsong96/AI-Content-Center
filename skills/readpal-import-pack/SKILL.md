# 分级阅读 word → 后台导入格式（拆包）

## 一、这是什么活儿

输入：一篇或多篇 word，**同一篇文章的多个难度混排在一个文件里**（正文 + 每级题目）。
输出：符合 ReadPal 内容后台导入规范的平铺文件包。

```
<标题>_A1.docx          正文（无标题行、无序号）
<标题>_A2.docx
<标题>_B1_母稿.docx      被标「母稿原文」的那一级加 _母稿
<标题>_题目.xlsx         一篇文章一个文件，每难度一个工作表（A1/A2/B1）
```

后台规则（Bryan 2026-09-24 给的原话）：
- **文件名即规范**：`标题_难度.扩展名`（母稿 `标题_难度_母稿.扩展名`；难度 `A1/A2/B1/B2+`）
- **同标题文件自动合并**为一篇文章的多个难度 → 所以标题串必须全篇一致，写错=整篇拆散
- 支持 `.doc/.docx/.txt/.md`，单批最多 **100 个文件** → 输出**平铺**，不要套子文件夹

## 二、铁律（Bryan 明确要求，违反就是返工）

1. **一个字都不能改内容**，只做切分 + 换格式。
   唯三例外：① 正文行首序号 `①②③…` 删除；② 题目里「卡片⑨」「card ⑦」→「第9段」；
   ③ 题目里泛指「段落」的英文 `the last card` → `the last paragraph`（**仅限指代段落，
   真实词义 `paying by card` 绝不改**，判定规则见第六节第 11 条）。
2. **不补题、不删题**。后台模板说明写「每级 5 题、仅解析前 5 题」，但**以原文为准**——
   原文 3 题就出 3 题。不要自作聪明补到 5 题。
3. **不改英文题面**。`What does "hard" mean in 第7段?` 这种中英混排就保持中英混排，
   不要改成 `Paragraph 7`。同理范围式引用的连接词 `to`/`and` 也按原文保留
   （`第7段 to 第9段`），要动必须先问。
4. **只读源文件**。绝不在源目录里改名/删除/覆盖。

## 三、干活的顺序

### 第 1 步：先侦察，别急着写代码

跑一遍结构扫描（`python3` 直接解 zip 里的 `word/document.xml`，不用装库）：

```python
import zipfile
from xml.etree import ElementTree as ET
W="{http://schemas.openxmlformats.org/wordprocessingml/2006/main}"
z=zipfile.ZipFile(p); body=ET.fromstring(z.read("word/document.xml")).decode("utf-8")
# 逐段打印 [pStyle] 文本
```

必须亲眼确认三件事：
- 标题段用的是哪个 pStyle（`DocTitle`？还是裸 `Normal`？）
- 难度标记行长什么样（`B1` / `B1（母稿原文）` / `B1版本` / `A1-`）
- 题目区起始标记是「题目」「练习题（A1- · 语言2 + 文本1）」还是「Questions」

**不要一套规则盲拆。** 已知至少 5 种结构变体（见第七节）。

### 第 2 步：先跑 1 篇，给 Bryan 看

```bash
python scripts/build_import_pack.py "<源docx>" "<输出目录>" "<题目模板.xlsx>"
```

让他确认为止。他常会在这一步纠偏（序号、命名、难度写法）。

### 第 3 步：确认后再批量

```bash
python scripts/batch_import_pack.py "<源目录>" "<输出目录>" "<题目模板.xlsx>"
```

`batch_import_pack.py` **内建核验**，跑完直接打印异常清单——
`verify()` 会逐字比对正文、逐字段比对题目 8 列，异常在终端里以 `⚠` 标出。
**不要把「代码跑完」当成「做完了」，必须看到异常数 = 0。**

跑前先估算文件数（篇数 ×（级数 + 1））。超过 100 就先按篇切上传批，别让 Bryan 自己挑。

### 第 4 步：生成校验表 + 给文件

用 `verify()` 的输出生成 `output/校验表.md`（逐篇 × 段落数/题数/校验结果）——

```bash
python scripts/gen_report.py > output/校验表.md      # 多批合并，改脚本里的 BATCHES 路径
```

再用 `present_files` 把产出文件与校验表一起交出去。
交付话术要带**变更清单**和**核验口径**，Bryan 只认「真跑过的证据」。

## 四、题目 xlsx 的硬规范

模板：`~/Downloads/ReadPal题目上传模板.xlsx`（副本在 `scripts/templates/` 若已缓存）。

- **一篇文章 = 一个 xlsx**，一次上传覆盖该篇全部难度 → 不要按难度拆成多个文件
- 每难度一个**工作表**，工作表名 = 难度名（`A1` / `A2` / `B1` / `B2+`）
- 表头固定 8 列：`题型 | 题干 | 选项A | 选项B | 选项C | 选项D | 正确答案 | 解析`
- 题型：单选 / 多选 / 判断；正确答案填**字母**，多选用 `A;C`
- 克隆模板生成（`openpyxl.load_workbook(template)` + 改 sheet 名 + `delete_rows(2, max_row)`），
  这样表头样式/列宽/数据有效性都跟着走

## 四点五、母稿怎么认（2026-09-24 Bryan 补充）

**规则：默认最高等级就是母稿。**

两种情况 `parse_docx` 都处理了：
1. 文档里**显式**标了——如 `B1（母稿原文）`、`B2+（母稿原文）` → 用它标的那一级；
2. **没标**——自动取该篇**最高**那一级做母稿，并在 `levels[lv]["mother_inferred"]=True`，
   `run()` 的 report 里会带「（未标母稿，按最高级推断）」。

实测三批：高级8 是 B1（3 级，B1 显式标）；新闻B2+ 是 B2+（4 级，B2+ 显式标）；
中国文化20篇 是 B2+（4 级，**文档内无标记**，靠「取最高级」推断命中 Bryan 的口头口径）——
即**同一套脚本能同时吃 3 级与 4 级文档**，不用改配置。

## 五、难度写法映射

`LEVEL_OUT` 是唯一出处：

```python
LEVEL_OUT = {"A1-": "A1", "A1": "A1", "A2": "A2", "B1": "B1", "B2+": "B2+", "B2": "B2+"}
```

⚠️ source 里写 `A1-`，输出要写 **`A1`**（Bryan 2026-09-24 定的）。
表名与文件名都用输出写法。**后台如果认不出难度，整级会被静默忽略**——所以这条要跟他确认过再跑批。

## 六、踩过的坑

1. **枚举式卡片引用必须整体改写——这是最容易漏的一条。**
   `卡片⑨和⑩` 只改第一个会剩个孤零零的 `⑩`，变成「第9段和⑩」（Bryan 看不出对错，但后台读着别扭）。
   必须一次吃下整串：`卡片⑥、⑧和⑩` → `第6段、第8段和第10段`；
   `卡片③到⑩` → `第3段到第10段`；`卡片⑦、⑧、⑨、⑩` → `第7段、第8段、第9段、第10段`。
   分隔符白名单：`和 及 与 到 至 to ~ 、 ， , / and – —`（**不要**加半角 `-`，会误伤英文）。
   **复数 `cards` 也要覆盖**（2026-09-24 BBC 50篇实测）：源文里存在
   `How do cards ⑦ to ⑨ relate to card ⑥?`、`cards ③–⑥` 这类写法，
   正则只写 `card|Card` 会整片漏掉，留下裸圈号。词表用 `(?:卡片|cards?|Cards?)`。
   实现见 `fix_refs()` 的 `CARD_GROUP_RE`，改完**务必**跑「圈号残留」检查兜底——
   看产出里还有没有裸的 `①②③`，实测就是靠这条抓到 `卡片③到⑩` 和 `cards ⑦ to ⑨` 的漏网。
   **替换顺序也有坑（2026-09-24 中国文化20篇实测踩到）**：`同一张卡片里` 如果先跑
   `replace("卡片","段")`，会变成 **`同一张段里`**（畸形）。必须按长→短：
   `张卡片` → `张卡` → `卡片`，结果才是 `同一段里`。已加「畸形检查」兜底
   （产出不得含 `张段/段片/段卡`）。
2. **文件名非法字符不要替换成 `-`，要直接删。**
   第 2 篇文档内标题是 `Whales: Swimming Mammals 鲸：会游泳的哺乳动物`（半角冒号），
   删掉冒号 + 合并多空格后**正好等于源文件名**——用 `-` 替换会凭空多出一个用户没要求的新差异。
3. **正文要复用源 docx 的 styles.xml**，不要从零造 docx。
   源正文段落大多是 `Normal` 样式 + **无直接格式**，所以「同样 pStyle 重建 + 带源 styles.xml」渲染结果一致。
   验证方法：解出源 `word/styles.xml` 看 `Normal` 的 `rFonts/w:sz`，再确认正文段 `w:rPr` 是空的。
4. **`stem` 不要做空白归一化**（`re.sub(r"\s+"," ")`）——那是在改内容。只在拼接处 `" ".join` 时自然合并。
5. **选项「四个挤在一段」要切分**：`(?<![A-Za-z0-9])([A-H])\s*[.．、:：]\s*`，
   负向先行断言必须有，否则会把英文单词里的 `a.`/`b.` 误切。
6. **答案/解析标签要中英双语**：`答案|Answer|正确答案`、`解析|Explanation`，
   且解析里可能带 `**答案：X。解析：**` 的残渣，解析前先 `.replace("*","")`。
7. **`①②③` 序号**：正文里是**真字符**（不是 Word 自动编号）。检查源段有没有 `numPr`，没有就直接正则删。
8. **核验脚本的 title 要用 `run()` 返回的「已消毒标题」**，不要用 `parse_docx()` 的原始标题——
   否则含非法字符的那两篇会假报「文件缺失」。
9. **`verify()` 的比对是「同源同函数」，测不出 fix_refs 自己的漏改**——
   因为源侧与产出侧都跑同一个 `fix_refs`。所以必须**另加独立检查**：
   ① 产出里不得出现「卡片 / 张卡 / 卡+序号」；② 产出里不得残留任何 `①②③`（枚举漏改只会在这里暴露）；
   ③ 产出里不得出现 `张段 / 段片 / 段卡` 畸形；④ 产出里不得残留泛指 `the ... card(s)`。
   四条已内建进 `verify()`。
   **再加一条「反向」检查**：把产出里剩余的 `card(s)` **逐条打印出来人工看一眼**，
   确认真实词义没被误伤。只看残留计数=0 不够——本次就是靠打印才发现
   `第7段 to 第9段` 这个漏改（计数是 0，但连接词没换）。
10. **残留检查别用 `"卡" in s` 这种粗口径。**（2026-09-24 中国文化批实测）
   `闪卡（flashcard）` 是正常词义，粗口径会假报「「卡片」残留 2 条」，让人白查一轮。
   要匹配**引用形态**：`卡片|张卡|卡\s*[①-⑳㉑-㉚]|(?<![A-Za-z])(?:cards?|Cards?)\s*(?:[①-⑳㉑-㉚]|\d{1,2})(?![A-Za-z])`。
   **`(?<![A-Za-z])` 这个负向断言必须有**——否则 `flashcards` 里的 `cards` 会被误判成残留
   （BBC 批实测：加上 `cards?` 后立刻冒出 1 处 `flashcards` 假报）。
11. **不带编号的 `card/cards` —— 已拍板按「A 方案」改写（2026-09-24 Bryan 确认）。**
   源文题干里的泛指引用**混着真实词义**，必须窄口径区分：

   | 类别 | 例子 | 处理 |
   |---|---|---|
   | 指代段落 | `the last card` / `the second card` / `the last two cards` / `the cards about Los Angeles` / `the cards before it` | ✅ → `paragraph(s)` |
   | 真实词义 | `paying by card` / `People paid with cards instead of cash` / `Cash is better than cards` / `credit and debit card transactions` | ⛔ 不动 |

   **唯一可靠的判定规则：只认「`the` + [序数/数量] + `card(s)`」**
   （序数白名单 `last|first|second|third|fourth|fifth|final|next|other|remaining|previous|earlier|following|above`，
   数量 `one|two|three|four|five`）。真实词义**都不带定冠词 `the`**，天然落在规则外——
   这比用「黑名单排除 credit/flashcard」稳得多，不会因为漏列一个词就误改。
   `flashcards` 靠 `(?<![A-Za-z])` 断言免疫。实现见 `BARE_CARD_PARAGRAPH_RE` + `rep_bare()`。
   **大小写要保留**（`The last card` → `The last paragraph`，别硬写小写 `the`）。

   实测改写量：新闻B2+ **16** 处、BBC 50篇 **15** 处、高级8 与文化批 **0** 处；
   真实词义保留：BBC 50篇 **3** 处（其余批 0）。改完必须让「泛指 card 残留 = 0」且
   「剩余含 card 的文本逐条打印出来人工确认为真实词义」——只看计数不够。

   **⚠️ 已知遗留（不要自己动，等 Bryan 发话）**：英文题面里的**连接词**按原文保留，
   会出现 `How do 第7段 to 第9段 relate to 第6段?`、`第7段 and 第8段` 这类中英混排。
   **BBC 50篇 16 处**，其余批 0。（Bryan 曾说「不用改」，指的是中英混排本身可接受；
   但 `to`/`and` 要不要换「到」「和」他没明确表态，别擅自改。）
12. **源目录会被 Bryan 重组，别把路径写死在脑子里。**（2026-09-24 实测）
   他把 `Desktop/分级文章/` 拆成了 `V1/`（旧）与 `V2/`（新），`高级8`、`中国文化20篇`、
   `BBC 50篇`、`高级7` 都在 `V2/` 下。跑批前**先 `ls` 一下**，
   拿到「共 0 篇」八成是路径失效，不是内容有问题。搬家后内容可能完全一致
   （实测 V1 vs V2 的高级8：15 篇 md5 全同），用 md5 对比确认后再重跑。
13. **单批 100 个文件的限制要提前算。**（2026-09-24 BBC 50篇）
   50 篇 × 5 个文件 = 250 个 → 必须分 3 次上传。用 `scripts/split_upload_batches.py`
   按篇切成每批 ≤100 个（切分保证**同一篇的 5 个文件同批**，避免同标题跨批）。
   注意别用 `rm -rf` 清理旧批次目录——文件数超 50 会触发 safe-delete 拦截，
   导致 `&&` 短路、后面的命令全不执行（这次就是这么踩的，白跑一轮）。
14. **不要自己去翻用户的其它目录**。他说「其他文章我单独发你」就是硬边界，
   `Desktop/分级文章` 里没点名的批次一律不碰。
   他发 zip 时，解压到**工作区**（`work/<批次名>_源/`），别往桌面写。
