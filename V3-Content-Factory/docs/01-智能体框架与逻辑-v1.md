# 分级阅读内容生产智能体 · 框架与逻辑 v1

> 这份文档回答三个问题：**它是什么 · 它怎么工作 · 为什么这么设计**。
> 配套文档：`Demo规格-分级阅读内容工厂-v1.md`（接口与数据细节）· `裁判提示词-v0-无判据版.md`（裁判提示词本体）· `金标准-example_honesty.md`（裁判验收尺）
> 日期：2026-09-28

---

## 0. 一句话定义

**输入一篇英文原文（B2+），输出一套可直接交付的分级阅读材料：**

> 四个难度的文章（A1- / A2 / B1 / B2+）＋ 每个难度 3 道题（合计一套 12 道）＋ 质检报告
> → 可在平台上阅读、编辑、导出 docx。

---

## 1. 定位与边界

| | 内容 |
|---|---|
| **是什么** | **内容工厂**（项目代号 V3）。上游接教研给的素材，下游交付成品。 |
| **产出物** | 4 篇不同难度文章 + 1 套题目（四级各 3 道）+ 质检报告 |
| **平台内有什么** | 生产台 · 阅读编辑器 · 质检面板 · 导出 |
| **下游是谁** | 另有**后台管理系统**负责导入、再处理 → 再上线到 **APP** |
| **本期不做** | 自适应难度调节（用户读着自动切级别）· 发布分发 · 账号权限 · 多维知识库 |

**关于「阅读编辑器」的定位要说清**：它是**审校窗口**，不是面向终端用户的阅读产品。
存在的理由是验收标准 V4/V5 —— 领导、同事必须**亲眼看到**四篇文章长什么样、**亲手改**一张卡，
只给 JSON 他们判断不了。真正的用户阅读体验由 APP 侧承担。

---

## 2. 它是什么形态的智能体

**流水线式智能体（Pipeline Agent）：2 个模型 + 1 个确定性脚本 + 1 个循环控制器。**

| 组件 | 角色 | 用什么 |
|---|---|---|
| **模型 A** | 生成者（改写 / 出题 / 局部重写） | GPT 系 |
| **模型 B** | 裁判（只判对错，不改稿） | DeepSeek 系推理模型 |
| **脚本** | 确定性质检器 + docx 渲染 | 老师的 `build_cards.py` |
| **控制器** | 串起流程、管重试与轮次上限 | 后端服务 |

**它不是**：多 agent 协作框架（不需要）· 也不是单模型一把梭（那样没有可验证性）。

**架构定性理由**：模型 A 与模型 B 的角色分离，**本身已经是 multi-agent 的最小形态**。
再往上拆（一个查事实、一个查语法、一个查题目）只在需要多种专长时才值得 —— 现阶段不值，
只会重现 V1 的"串联失真"（见 §11）。

## 3. 全局架构

```
                  ┌─────────────────────────────────────────────┐
   输入           │  ① 生成 · 模型 A（GPT 系）· 单次调用         │
 英文原文 B2+ ───► │    产出：A1-/A2/B1 三级正文 + 四级题目        │
                  │          + b2_card_starts（B2+ 切卡锚点）     │
                  └────────────────────┬────────────────────────┘
                                       ▼
                  ┌─────────────────────────────────────────────┐
   关卡一         │  ② 形式校验 · 确定性脚本（15 类）             │
  形式层          │    判：卡片数 / 词数占比 / 句长 / 语法信号词   │
  （全自动）      │        / 主题词 / 专有名词 / 题目结构 / 引用一致 │
                  └────────────────────┬────────────────────────┘
                                       ▼ 有问题 → 局部重写 → 回到 ②
                  ┌─────────────────────────────────────────────┐
   关卡二         │  ③ 语义裁判 · 模型 B（DeepSeek 系）           │
  语义层          │    判：内容一致性 / 事实保真 / 跨级衔接        │
  （自动 + 兜底） │        / 明显超纲（不给词表，凭读者水平判断）  │
                  └────────────────────┬────────────────────────┘
                                       ▼ 有 P0 → 局部重写 → 回到 ②
                  ┌─────────────────────────────────────────────┐
   交付           │  ④ 渲染 · 确定性脚本                          │
                  │    JSON → 结构化数据（供下游）+ docx（给人）   │
                  └────────────────────┬────────────────────────┘
                                       ▼
                  ┌─────────────────────────────────────────────┐
   审校           │  ⑤ 阅读编辑器 · 平台界面                     │
                  │    四级切换 / 卡片与题目就地编辑 / 手动重跑    │
                  └─────────────────────────────────────────────┘
```

**全链路只有两类模型调用**：生成类（模型 A，含局部重写）· 裁判类（模型 B）。
其余全部是确定性代码。

## 4. 五个环节逐环说明

### ① 生成（模型 A · GPT 系）

| | |
|---|---|
| **做什么** | 读原文 → 降级改写为 A1- / A2 / B1 三级正文 → 出四级题目 → 给出 B2+ 的切卡锚点 |
| **调用次数** | **1 次**（绝不拆成多次） |
| **输入** | 英文原文全文（B2+） |
| **输出** | 严格 JSON：3 级卡片 + 4 级题目 + `b2_card_starts` + `topic_words` + `title_en/title_zh` |
| **提示词** | **直接复用**佳阳老师《项目说明》全文，不改 |
| **失败处理** | JSON 解析失败 → 原样重试 1 次；仍失败 → `status: failed` |

**两个要点：**

1. **B2+ 不生成。** 「B2+ 就是原文，不要重新输出原文」——老师原文规定。
   系统只按 `b2_card_starts` 把原文切成卡。所以**只有 3 条生成链路，不是 4 条**。
2. **为什么必须一次调用。** 见 §10 第 1 条。

---

### ② 形式校验（确定性脚本 · 关卡一）

**这是"稳"（验收项 A）的落点 —— 不靠模型更聪明，靠脚本挡掉不合格的。**

分两批：老师的 14 类（现成）+ 建议新增的 1 类。

**判错（会触发 `需修改 N 处`）**

| # | 规则 | 来源 |
|---|---|---|
| 1 | 各级卡片数与 B2+ 张数对齐 | 老师 |
| 2 | 词数占比在区间内（A1- 30–42% / A2 48–60% / B1 65–78%） | 老师 |
| 3 | 单句不超该级最长词数（12 / 16 / 22） | 老师 |
| 4 | 任一主题词不得缺失 | 老师 |
| 5 | 题目数 = 3 | 老师 |
| 6 | 选项数 = 4 | 老师 |
| 7 | 答案字母有效 | 老师 |
| 8 | 解析引用的英文逐字存在于本级正文 | 老师 |
| 9 | 题干引用的英文逐字存在于本级正文 | 老师 |
| 10 | 卡片起始句能在原文找到 | 老师 |
| 11 | 第一张卡从原文开头开始 | 老师 |
| **12** | **A1- 正文必须保留原文中的关键人名 / 地名** | **建议新增** |

**仅警告（只提示，不判错）**：⑬ 句子短于该级最短词数 · ⑭ 出现可能超纲的语法信号词 · ⑮ 某级三题答案字母全相同

> **第 12 类为什么必须加**：佳阳老师明确规则 —— **关键人名、地名必须保留，可加同位语解释身份
> （`Graves, a scientist` ✓），但不能泛称替代（`A scientist` ✗），且不受"A1- 最多 3 个专有名词"限制。**
> 而老师原脚本里**一行相关代码都没有**（grep 过，0 命中）。这条又恰好能机械化检查 → 从"靠人看"变成"脚本拦"。

**已知覆盖缺口（诚实标注）**：
- 引用校验只认 ≥3 个词的引用，**引用 2 个词即漏检**
- 引用是子串匹配、无词边界，**跨卡拼凑的字符串也能过**
- 全部校验只看形式，**内容对不对一概不管**（这正是关卡二存在的理由）

---

### ③ 语义裁判（模型 B · DeepSeek 系推理模型 · 关卡二）

**这是"内容达标"（验收项 V3）的落点。也是本期唯一需要新写的提示词工程。**

| | |
|---|---|
| **做什么** | 拿四级卡片互相对照 + 对照原文，找出内容层问题。**只判不改。** |
| **输入** | 原文 ＋ 按卡对齐的四级卡片（第 N 张卡的四个版本为一组）＋ 四级题目 |
| **输出** | `{ findings: [{ level, location, type, original, rewritten, why }], conclusion }` |
| **提示词** | `裁判提示词-v0-无判据版.md`（详见 §8） |
| **返回内容** | **不返回改后的正文**，只返回问题与依据 |

**裁判查的 8 类问题**

| # | type | 含义 | 严重度 |
|---|---|---|---|
| 1 | `fact_added` | 低级别新增了原文没有的事实 | P0 |
| 2 | `fact_dropped` | 核心事实被删除 | P0 |
| 3 | `fact_altered` | 主体 / 立场 / 确定性程度被改变 | P0 |
| 4 | `card_misaligned` | 第 N 张卡在各级讲的不是同一件事 | P0 |
| 5 | `bridge_broken` | 承上启下信息被删，跨级降读断裂 | P1 |
| 6 | `topic_word_weak` | 主题词出现了，但语境不足以推断词义 | P1 |
| 7 | `answer_unsupported` | 答案在本级正文里找不到依据 | P0 |
| 8 | `option_unfair` | 干扰项不合理（无出处 / 与正确答案同义） | P1 |

> 原草案有第 9 类 `topic_word_missing`，**已删除** —— 脚本第 4 类已硬性拦截，裁判重复查只烧 token。
> **原则：裁判只做脚本做不了的判断。**

---

### ④ 渲染（确定性脚本）

- **结构化数据**：`cards.json` 形态的四级对齐数据 → 交给下游后台系统
- **docx**：用老师的 `template.docx` 渲染 → 给人看、给下游存档

**为什么必须是结构化 JSON 而不是一份 docx**：下游的编辑与（未来的）自适应阅读都要**按段取不同难度**，
docx 表达不了"第 N 张卡的四个级别版本"这种对齐关系。

---

### ⑤ 阅读编辑器（平台界面）

| 能力 | 说明 |
|---|---|
| 四级切换 | A1- / A2 / B1 / B2+ 一键切换，同一张卡纵向对比 |
| 就地编辑 | 任何一张卡、任何一道题都能改，改完保存 |
| 手动重写 | 「重写这张卡」——调模型 A，只重出这一张 |
| 重跑质检 | **两级按钮**（见 §7） |

## 5. 两条质量主线（你定的两个核心）

**整个智能体的设计，最终只服务这两条线。其他都是手段。**

### 主线一：四级内容大意保持一致

| 问题 | 谁防 |
|---|---|
| 四级讲的不是同一件事 | 裁判 `card_misaligned` |
| 新增 / 删掉 / 改动事实 | 裁判 `fact_added` / `fact_dropped` / `fact_altered` |
| 跨级连续阅读接不上 | 裁判 `bridge_broken` + 脚本第 12 类（人名保留） |
| 主题词丢失 | 脚本第 4 类（硬拦截） |
| 主题词在但没语境 | 裁判 `topic_word_weak` |

**关键背景**：读者会**跨级连续读**（读完 A1- 第 1 段，接着读 A2 第 2 段）。
所以"四级一致"不是加分项，是**硬需求**。由此推出一条老师那版没有的约束：

> **降级不得删掉「承上启下」的信息。** A1- 的卡可以简化，但不能把下一张卡要用的那句话头删了。

### 主线二：语言难度符合对应等级

| 受众映射 | 级别 | 中国学段参照词汇量 |
|---|---|---|
| 小学生 | A1- | 505（义务教育课标 2022 二级） |
| 初中生 | A2 | 1600 |
| 高中生 | B1 | 3500（高中课标 2017/2020） |
| 高中生以上 | B2+ | 4795（大学四级） |

| 检查层 | 手段 | 状态 |
|---|---|---|
| 词数总量 | 脚本（占比区间） | ✅ 有 |
| 句长 | 脚本（上下限） | ✅ 有 |
| 语法超纲 | 脚本（信号词，14 个词）+ 裁判 | ⚠️ 现有提示较弱 |
| 词汇超纲 | 裁判（**不给词表**，凭读者水平判断） | ✅ 已定方案 |

**不给词表的理由（你定的，我同意且补了证据）：**

1. 词表是**累计列表**，只能判"在不在表里"，判不了"**这个词在这个语境里能不能被猜出来**"
   —— 而老师方法论恰恰要求"主题词首次出现要给足可推断词义的语境"。
2. **词表会跟硬要求打架**：主题词（`honesty`）本身偏难但必须保留 → 给词表就会判它超纲 → 触发重写改掉它。
3. 真正的风险不是个别难词，是**整体复杂度失控** —— 而那个已被脚本管住。
4. **实证**：核对老师示例时发现，A1- / A2 / B1 **三级都把 `unscrupulous` 简化成了 `cheat`**
   —— 没有任何提示，模型自己就知道这个词太难。

**两条护栏**：只报**明显超纲**（边缘情况不报）· **主题词与专有名词豁免**，即使偏难也不算超纲。

## 6. 自动修复循环（完整决策逻辑）

**原则：只要不达标就自动修，直到达标或到上限；上限到了才交给人。**

```
① 生成（模型 A）
   │
   ▼
② 形式校验（脚本）  ──有错──►  局部重写（只重出报错的卡/题，模型 A）──┐
   │                                                              │
   │  0 错                                    最多 3 轮 ◄──────────┘
   ▼
③ 语义裁判（模型 B）
   │
   ├─ 有 P0 ──► 局部重写相关卡 ──► 回 ② ──► 回 ③      （最多 2 轮）
   │
   └─ 只有 P1 ──► 不自动改，只标记，交人工决定
   │
   ▼ 无 P0
④ 渲染 → ⑤ 完成

若超出轮次仍有错 → 停止，标记 needs_human，把问题清单（定位到卡/句）交给编辑
```

**四条设计理由**

1. **必须有轮次上限。** 3 轮（形式）+ 2 轮（语义）。不设上限会死循环并持续烧 token。可配。
2. **只做局部重写，不整篇重跑。** 脚本和裁判都能定位到具体卡片，只重出那一张 —— 这正是老师原设计
   「重写 B1 / 修改 A2 Q2」的用法，也是最省 token 的做法。
3. **P0 自动修，P1 只报告。** P0 是硬伤（事实错了、跨级断了），改了只会更好；
   P1 是"是否要改取决于教研口径"，机器不该替人拍板。**这就是"人只发挥最关键的作用"的落点。**
4. **兜底交人。** 机器修不动 → `needs_human` → 编辑接手。

**状态机**（`GET /api/jobs/{job_id}` 返回）

```
pending → generating → checking → auto_fixing ─┐
                                     ↑         │
                                     └─────────┘
                          → judging → auto_fixing → rendering → done
                                     ↓
                              needs_human / failed
```

## 7. 人机分工边界

| 环节 | 谁做 | 自动 / 人工 |
|---|---|---|
| 生成 | 模型 A | 自动 |
| 形式校验 | 脚本 | 自动（毫秒级、免费） |
| 形式层修复 | 模型 A | **自动**，3 轮 |
| 语义裁判 | 模型 B | 自动（要调 API、慢、花钱） |
| 语义层 P0 修复 | 模型 A | **自动**，2 轮 |
| 语义层 P1 处置 | 人 | **人工**（机器不替人拍板） |
| 超轮次兜底 | 人 | **人工**（`needs_human`） |
| 阅读、编辑 | 人 | 人工 |
| 导出 | 脚本 | 自动 |

**手动重跑质检分两级（你定的方案，我补了理由）：**

| | 是什么 | 成本 | 触发方式 |
|---|---|---|---|
| **L1 重跑** | 脚本质检 | 毫秒级、免费 | **按钮，随便点** |
| **L2 重跑** | 模型裁判 | 贵 + 慢 | **单独一个按钮**，人决定要不要花 |

> 为什么分两级：老师手改大概率改的是**内容层**（脚本判不了的那些）——
> 改完形式质检照样全绿，"循环点按钮到通过为止"是**空转**。
> 而模型裁判要花钱，不该顺手就跑。这两件事性质不同，必须分开。

## 8. 裁判提示词：v0 无细判据版的逻辑

**这是你拍板的方案，也是这份架构里最"反直觉"的一处设计。**

### 核心思想

> **给它"为什么"，不给"什么算错"。**

提示词里只给三样东西：**读者是谁 · 怎么读 · 要保住什么**。
零条判定细则。判断权交给模型。

### 三条依据

1. **"没有判据"在物理上不存在。** 提示词总要写东西，写了的都是判据。真正可选的是**粒度**：
   - A 档：只给任务（"看看有没有问题"）
   - B 档：类名 + 例子 ← 规格文档是这档
   - C 档：边界细则 + P0/P1 分级 ← 我原提议的"判据确认表"才到这档

   **你选的是"停在 B、甚至退到 A"。我同意** —— 理由见第 3 条。

2. **判据与知识必须分开。**
   - **判据**（什么算"同一件事"）= 口径问题 → **可以不给**，让模型自己判
   - **知识**（各级词汇表、语法清单）= 事实问题 → **必须喂**，否则它无从判起
   - 你担心的"判坏了"，真正的来源不是判据，而是**「误报 → 自动重写」这条链**。
     现在 P1 不自动改、超轮次交人，误报的代价已经从"内容被改坏"降到"多一条提示"。

3. **模型能泛化"目标"，只能照搬"规则"。**
   "用第一性原理判"这句话本身不会让它更准（那只是风格指令）；
   但**目标导向**的写法会：给"小学生读不懂就报"，比给"以下 7 种情况算超纲"更能泛化。

### 提示词的 5 条关键约束

| 约束 | 为什么 |
|---|---|
| **宁可漏报，不要误报** | 误报会触发无谓重写，把合格内容改坏。第一版调性就是"宁缺勿滥" |
| **不给词表** | 见 §5 主线二 |
| **主题词 / 专有名词豁免超纲** | 否则会跟"A1- 必须保留主题词"打架 |
| **只报问题，不给修改建议** | 给建议会诱导它为了"有建议"而虚构问题 |
| **必须给双向引用**（原文怎么写 / 改写怎么写） | 拿不出引用的，不许报 —— 这是误报的天然闸门 |

### 升级路径（不够用才加，一次只加一种）

```
v0   → 实测漏报/误报
v0.1 → 漏报严重 → 加"事实逐条比对"流程约束（仍不给细则）
v0.2 → 误报严重 → 收紧报告门槛（必须双向引用）
v0.3 → 某类系统性漏判 → 只给那一类的细则
v1.0 → 都收敛后，再补 P0/P1 与自动重写
```

> **不要一次性把 8 类细则全写进去。** 那是 V1 的老路：先堆规则，再发现规则互相打架。

## 9. 数据流与存储

**存储：JSON 落盘**（你定的）。沿用老师的目录结构，不另设 schema：

```
data/articles/{article_id}/
    original.txt          # 原文（B2+）
    cards.json            # 四级卡片 + 题目 + b2_card_starts（老师已定义的格式）
    check_report.json     # 14(+1) 类脚本校验结果
    judge_report.json     # 语义裁判结果
    fix_log.json          # 自动修复留痕（轮次 / 范围 / 改前 / 改后）
```

**Article 对象**

```
Article {
  id, title_en, title_zh, topic_words[],
  original_text,                             // B2+ 原文
  b2_card_starts[],                          // B2+ 切卡锚点（每卡开头 4 词）

  levels: {
    "A1-": { cards: [string], questions: [{q, options[4], answer, explanation}] },
    "A2":  { cards: [...], questions: [...] },
    "B1":  { cards: [...], questions: [...] },
    "B2+": { questions: [...] }              // 正文 = original_text 按 b2_card_starts 切出
  },

  check_report: { stats[], errors[], warnings[], passed },
  judge_report: { findings[] } | null,
  fix_log:      [ { round, scope, target, before, after } ],

  status, created_at, updated_at
}
```

> `fix_log` 是必需的 —— 没有它，将来没人能回答"老师改了哪一处让结果从不通过变通过"。

## 10. 八条关键设计判断（含为什么）

| # | 判断 | 理由 |
|---|---|---|
| 1 | **生成只调 1 次，绝不串联** | 多步串联 = 多次信息损耗 + 0 次质量增益。V1 的病根（§11） |
| 2 | **能机械验证的一律用脚本，不交给模型** | 模型数词数不准还贵。词数/句长/引用逐字一致全部由脚本判 |
| 3 | **脚本在前，模型在后** | 脚本先筛，只把可疑项交给模型 —— 省 token；也避免用模型做确定性工作 |
| 4 | **裁判用异源模型** | 同一个模型倾向认为自己写得对（同源偏差）。**这就是为什么不能用我自己跑裁判** |
| 5 | **裁判只判不改** | 判和改合一会让模型倾向于"为了有得改而找问题" |
| 6 | **只局部重写，不整篇重跑** | 最省 token；且正是老师原设计的用法 |
| 7 | **必须有轮次上限** | 无上限的死循环会持续烧钱 |
| 8 | **P0 自动 / P1 人工** | 硬伤机器改只会更好；口径问题不替人拍板 |

**两个明确的反模式（不做）**

- ❌ **不用模型的自我反思**（让 A 自己评自己）—— 有确定性脚本做外部反馈，比自评可靠得多
- ❌ **不拆多 agent** —— 改写和出题吃的是同一份原文、同一次判断，拆开只会重现串联失真

## 11. 与 V1 的对照：为什么这次不会重蹈

| | V1（已放弃） | 本方案 |
|---|---|---|
| 模型调用 | 8 个工作流串联 | **1 次生成 + 1 次裁判** |
| 质检 | **0 个确定性校验**，靠 AI 自评 | **15 类脚本校验**，机器判形式 |
| 内容层把关 | 无 | 异源模型裁判 |
| 信息流 | 每一步都是纯 AI 翻译，只累积误差 | 每一步要么注入外部标准（脚本），要么做独立判断（裁判） |
| 验收 | 无口径，无法判断好坏 | 6 项可验证标准，V2 是硬门槛 |
| 失败模式 | 质量差 → 加提示词 → 加工作流 → 更差 | 差 → 定位到具体卡 → 局部重写 |

**一句话**：V1 用它"编排了多少步"来证明价值，本方案用**"裸模型给不了什么"**来证明价值。

## 12. 验收标准（这是"可验证"的定义）

**谁来验**：领导、你、同事，三方各自独立跑一遍。

| 编号 | 可验证项 | 判据 |
|---|---|---|
| V1 | 能出内容 | 粘贴原文 → 界面上拿到四个难度的成稿 |
| **V2** | **形式达标** | **质检报告显示 `通过`（0 错误）** ← **硬门槛，不通过后面不用看** |
| V3 | 内容达标 | 裁判报告无 P0；抽检 3 张卡，四级讲的确实是同一件事 |
| V4 | 门槛低 | 操作者不写提示词、不装环境、不看代码，只用界面 |
| V5 | 可编辑 | 任何一张卡、任何一道题都能就地改，改完能重跑质检 |
| V6 | 可交付 | 能导出与老师模板一致的 docx |
