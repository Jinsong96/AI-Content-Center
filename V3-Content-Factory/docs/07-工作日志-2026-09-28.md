### Bryan 答 Q1（22:15）— 关键的机制补充

**内容质量第一位，且他指的实质是「跨级别一致性」。核心新信息：**

1. **最终交付对象是终端用户**，用户会读 A1/A2/B1/B2 的文章。改写不得让用户无法理解大意。
2. **主题词不能因为低级别语料没有就丢掉**（例：honesty 是主题词，A1/A2 也必须保留）。
3. **⭐ 自适应阅读机制（此前未知，重要）**：用户读文章时难度**动态调节**——
   读 A1 这一段觉得容易 → 下一段换成 A2 → 还容易 → 下一段 B1；觉得难则反向降。
   **即：用户读的是「同一篇文章、逐段混搭难度」的连续文本。**

**由此推出的推论（我的判断，已发出）**：
- 自适应把「四级卡片语义对齐」从加分项变成**硬需求**——用户从 A1 第 1 段接着读 A2 第 2 段，必须能接上。
- **新增改写约束（老师那版 skill 没有）**：降级**不能删掉「承上启下」的信息**，否则跨级降读时断裂。
- **输出形态推论**：要支持自适应，平台必须输出**带对齐锚点的四级结构化数据**（`cards.json` 已是此结构），
  不能只给一份 docx。

**对老师工具包质检覆盖度的精确评估**：
- ① 主题词保留 → **已强制**（`缺少主题词 "honesty"` 直接报错）；但只保证「词出现」，不保证「语境未被扭曲」，

→ ② ③ 是真缺口；内容层量化方案：加「四级对照裁判」（对照而非自评），但属**半自动**，最终仍需人工抽检。

### Bryan 质疑「判据」本身（22:53）— 采纳，改为 v0 无细判据版

**他的质疑（工程直觉，我认同）**：判据不好定；定太死或太松都会出问题，
**反而可能把第一模型生成的好内容判坏**。建议**先不加判据跑一遍看效果**，需要再加。
（另提"直接交给大模型用第一性原理判"。）

**我的分析（已发出）**：
1. **「没有判据」在物理上不存在** —— 提示词总要写东西，写了就是判据。真正可选的是**粒度**：
   A 档（只给任务）／B 档（类名+例子）／C 档（边界细则+P0P1）。
   **规格现在是 B 档**；我提议的"判据确认表"才推到 C。**他要的其实是"停在 B 或退到 A"，同意。**
2. **必须分开「判据」与「知识」**：判据（口径：什么算同一件事）可以不给；**知识（A1- 词汇表、各级语法清单）必须喂**，
   否则模型无从判起。**"超纲"判不了不是因为缺判据，是因为缺词表。**
3. **"判坏了"的真正来源不是判据，是「裁判误报 → 自动重写」这条链** →
   建议**第一版把裁判与重写解耦**：裁判只标记 → 给人看 → 人点"重写这张"。
   **与他前面"重跑质检要给按钮"是同一条逻辑**（凡可能误判的环节，先让人确认）。
4. **"第一性原理"四个字作为提示词不会更准**（只是风格指令）；但正确落地是**目标导向而非规则导向** ——
   给"为什么"（读者是谁、会跨级连续读、要保住什么），不给"什么算错"。**模型能泛化目标，只能照搬规则。**

可直接用的提示词本体（零细则，只给背景+任务+**"宁可漏报不要误报"**+JSON 输出格式）；

## 23:35 · V3 前端改版：改浅色 + 整体放大（Bryan 反馈）

**他的原话**：「整体颜色用浅色系，注意整体的美感和搭配，可以用简约大气的极简风格，
你目前还是可以的，主要是颜色。还有整体的适配，这个我在浏览器中打开太小了。」

**实测到的根因（不是感觉，是量出来的）**：
- 他贴的截图是 **4136×2180 物理像素（@2x）→ 逻辑视口 ≈ 2068px**
- 而 `.desk-inner` 上限只有 1080px、`body` 基准字号只有 14px
- → **内容只占屏幕宽度 52%，两侧各空 ~474px**，加上 14px 字号，观感必然"又小又空"

**改了什么**：
1. **默认主题换成浅色**（`<html data-theme="light">` + JS 兜底 `|| "light"`；深色保留为可切换项）
2. **重做配色为「纸白 + 墨黑 + 单一赤陶强调」**：bg `#f2f2f0` / surface `#fff` / text `#17181a` /
   accent `#c2410c`；侧栏与质检面板改**实心白**（原来是半透明混合），卡片加 `--sh1` 轻投影。
   深色主题同步换成中性墨黑（原来偏暖棕），共用同一套强调色变量。
3. **尺度全部流体化**：新增 `--fs-xs/sm/base/lg/read` 五个 `clamp()` 字号 token
   （`--fs-base` 15→18px、`--fs-read` 17→22px 随视口放大）；栏宽也 clamp
   （`--aside-w` 238→312、`--panel-w` 316→424）；`.desk-inner` 1080→1380、`.editor-inner` 900→1060。
   容器内所有 px 字号改吃 token，模板里的 8 处内联 `font-size` 也一并换掉。
4. **修了一个真 bug**：≤1040px 堆叠布局下 `.stage` 是 `flex:1 + overflow:hidden`，
   在 `main` 变纵向滚动时**被压成 0 高 —— 编辑区整块消失**。
   改 `flex: 0 0 auto; overflow: visible`。同时把级别切换条设为 sticky。
5. 桌面/窄屏断点重排：三列保留到 700px（换行会撑出大片空白），700px 以下才竖排；

## 00:20 · V3 加中英双语 + 明暗主题分段切换（Bryan 反馈）

**他的原话**：「背景色可以换成浅色吗，就是像WorkBuddy一样，有浅色和黑色的切换。
然后增加一个英文版本，在右上角可以切换中英文的版本。」

### 找到「改浅色没生效」的真因
`applyTheme()` 会把主题写进 `localStorage`。早期版本默认 `"dark"`，**老访客的 localStorage 里
已经存了 "dark"**，于是 `getItem(LS_THEME) || "light"` 永远取到 dark ——「默认浅色」对老用户不生效。
→ 换键 `v3.theme.v2`，一次性作废旧值。**这是个通用坑：改默认值的代码，必须先处理存量存储。**

### 做了什么
1. **顶栏两组紧凑分段控件**：`☀|☾` 主题、`中文|EN` 语言（用 `.seg-compact`，比图标按钮无歧义）。
   优先级一律 `URL 参数 > localStorage > 默认`，所以 `?lang=en&theme=dark` 可直接分享。
2. **前端全量 i18n**：`I18N.zh / I18N.en` 两张表 + `t(key, vars)`；静态标记走
   `data-i18n / -html / -ph / -title / -aria`，动态区域全部走 `t()` 重渲染。
   共 58 处标记、约 200 个键。文章标题按语言主次互换（中文界面主显 title_zh，英文主显 title_en）。
3. **后端质检报文结构化**：`_issue()` 新增 `params` + `hint_key`，14 类问题的模板搬进前端。
   中文界面仍用后端原文（更精确），英文界面用模板 + params 重渲染。
   **这是让「同一份报告双语显示」不用跑两遍质检的关键。**
4. **裁判语言跟随界面**：`llm.judge(..., lang)` 追加输出语言指令，`build_judge_input` 的
   标签也分中英；lang 从 `body.get("lang")` 一路透传到 `run_produce / run_fix / run_judge_loop`。
5. 修掉两处中英混排：语义裁判「未跑」占位（后端存的中文结论 → 改用界面语言固定文案）、
   任务进度按钮（原本直接显示后端中文 `job.step` → 改用 `stepLabel(job)` 本地化）。
6. `applyLangShell()` 拆出来同步先跑，避免首屏切换按钮出现短暂无选中态。
