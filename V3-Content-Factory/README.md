# 一鹿知 · 内容生产平台

> **本目录 = 仓库内的 `V3-Content-Factory/`，同时是唯一的发布目录。**
> **给这个仓库的 AI 或人：先读 [`AGENTS.md`](AGENTS.md)，再读 [`docs/00-需求澄清实录-grill-me.md`](docs/00-需求澄清实录-grill-me.md)。**
> 这两份决定你会不会做错方向。本文负责"这是什么、怎么跑、接口与规则是什么"。

一个**分级阅读内容工厂**：输入一篇原文，输出四个难度的文章 + 一套题目 + 质检报告。
定位是**内容工厂**，不是 APP —— 上游接教研给的原文，产出交给下游后台系统导入、再上线到 APP。
本目录所属的 V3 与 V1（内容生产后台）、V2（分级卡片页）**完全隔离**，是新建的干净项目。

## 它做什么

```
原文（B2 母稿 或 新闻原稿）
   │
   ├─① 生成      模型 A（deepseek-flash）· 单次调用
   ├─② 形式校验  确定性脚本 · 17 类规则，判词数/句长/语法/主题词/人名/题目结构/多义实词
   ├─③ 语义裁判  模型 B（Qwen3.8-27B @ siliconflow）· 只判对错不改稿，捉内容层问题
   ├─④ 渲染      确定性脚本 → 结构化 JSON（给下游）+ docx（给人）
   └─⑤ 审校      平台界面 · 四级切换、就地编辑、手动重写
```

**全链路只有两类模型调用**（生成 + 裁判），其余全是确定性代码。**零第三方依赖。**

### 设计原则（为什么是两关而不是八个工作流）

1. **能机械验证的一律用脚本，不交给模型** —— 数词、句长、引用是否逐字存在，模型数不准还贵。
2. **脚本在前，模型在后** —— 脚本挡形式，模型挡语义；先筛后判，省 token。
3. **裁判用异源模型** —— 同一模型倾向认为自己写得对。
4. **生成一次调用，绝不串联** —— 多步串联只累积失真，不累积质量。
5. **裁判只判不改**，严重度由系统按问题类型映射，不让模型替业务定优先级。

### 自动修复循环

```
生成 → 形式质检 ─有错→ 局部重写（只重出报错的那张卡）→ 回质检   [上限 3 轮]
         ↓ 0 错
      语义裁判 ─有 P0→ 局部重写 → 回质检 → 再裁判               [上限 2 轮]
         ↓ 无 P0
       渲染 → 完成
         ↓ 超出轮次
      needs_human（把问题清单交给人）
```

**P0 自动修，P1 只报告。** P0 是硬伤（事实错了、跨级断了），改了只会更好；
P1 是「要不要改取决于教研口径」，机器不替你拍板 —— 这就是「人只发挥最关键作用」的落点。

## 两种输入模式（`source_mode`）

| 模式 | 输入 | 输出 |
|---|---|---|
| **`b2`（默认）** | 一篇英文原文，等级已由人工判定（B2 母稿） | 向下生成 B1 / A2 / A1- 三级；**B2+ = 原文本身，不重新生成**，只切卡 + 出题 |
| **`news`** | 新闻原稿（长度/难度都不符 B2+） | **四级全部生成**，保真基准是新闻原稿 |

原稿太简单时 **提示、不硬升**：生成时自评 `source_level` → 落库 → 质检第 17 类
`source_level_low` 出 warning → 界面建议「换一篇更难的稿件」。

> **改 `b2` 链路时的红线**：不得影响 `b2` 模式的生成质量；新增模式要**另起提示词文件**，
> 不改正文件（生成与裁判都非确定性，原提示词改一个字旧结果就变）。

## 跑起来

```bash
cd V3-Content-Factory
python3 app.py 8801     # 只用 Python 标准库，无需 pip install
# → http://127.0.0.1:8801
```

`PORT` 环境变量优先（Railway 等平台会自动注入）。

首次启动后自带一篇示例文章（`data/articles/seed-example-honesty/`），即使没配密钥也能看到完整成品形态。
想重新导入：`python3 seed.py`。

### 配置模型（两条路，互不覆盖）

**路 A · 界面填**：右上角「**模型设置**」，存浏览器 localStorage，随请求体转发，
**不写服务器磁盘、不进代码仓库**。

**路 B · 服务端配**：
- 环境变量：`GEN_BASE_URL / GEN_API_KEY / GEN_MODEL`、`JUDGE_BASE_URL / JUDGE_API_KEY / JUDGE_MODEL`
- 或 `server_keys.json`（**本机文件，已 gitignore，权限 600**）—— 发布沙箱没有环境变量入口，
  线上必须走这个。**环境变量优先，文件只补空缺**；缺了不影响启动，只是要用就得自己填 key

**默认模型**（`DEFAULT_CONFIG`）：

| 角色 | base_url | model |
|---|---|---|
| 生成 | `https://api.deepseek.com` | `deepseek-flash` |
| 裁判 | `https://api.siliconflow.cn/v1` | `Qwen/Qwen3.8-27B` |

### 访问口令

`server_keys.json` 里的 `access_code`，校验所有 `/api/*`（静态页与 `/api/health` 放行）。
**未配口令时全部放行**，本地开发不受影响。口令通过后下发 Cookie `v3code`（docx 下载走
`<a href>` 跳转带不上自定义头，必须靠 Cookie）。前端遇 401 自动弹口令框。

## 接口一览（16 个）

所有 `/api/*` 受访问口令保护（未配口令时全放行）；口令用请求头 `X-Access-Code` 或 Cookie `v3code`。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | 健康检查（**不需要口令**） |
| GET | `/api/config` | 模型配置状态（不含密钥）。`ready` = 字段填齐 **且** 最近一次真实调用成功 |
| POST | `/api/config/probe` | 连通性自检（真打一次模型） |
| GET | `/api/articles` | 文章列表 |
| POST | `/api/articles` | 提交原文，启动生产（异步，返回 `article_id` + `job_id`；收 `source_mode`） |
| GET | `/api/articles/{id}` | 完整文章 |
| PUT | `/api/articles/{id}/cards` | 保存某张卡 |
| PUT | `/api/articles/{id}/questions` | 保存某道题 |
| POST | `/api/articles/{id}/rewrite` | 人工触发局部重写 |
| POST | `/api/articles/{id}/fix` | 一键自动修复 |
| POST | `/api/articles/{id}/check` | **L1 重跑**：形式质检（免费、毫秒级） |
| POST | `/api/articles/{id}/judge` | **L2 重跑**：语义裁判（要花一次模型调用） |
| POST | `/api/articles/{id}/export` | 导出 docx |
| GET | `/api/articles/{id}/export/download` | 下载 docx |
| GET | `/api/jobs/{job_id}` | 轮询任务进度 |
| DELETE | `/api/articles/{id}` | 删除文章 |

> L1 / L2 分开是有意的：老师手改后重跑形式质检是免费的，随便点；
> 模型裁判要花钱花时间，单独一个按钮由人决定。

## 质检规则（17 类：判错 12 + 警告 5）

**判错（触发 `needs_human` 或自动修复）**

| # | 规则 | 来源 |
|---|---|---|
| 1 | 四级卡片数对齐 | 老师 |
| 2 | 词数占比在区间内（A1- 30–42% / A2 48–60% / B1 65–78%） | 老师 |
| 3 | 单句不超该级最长词数（12 / 16 / 22） | 老师 |
| 4 | 任一主题词不得缺失 | 老师 |
| 5–7 | 题目数 3 / 选项数 4 / 答案字母有效 | 老师 |
| 8–9 | 解析与题干引用的英文逐字存在于本级正文 | 老师 |
| 10–11 | 卡片起始句能在原文找到 / 第一张卡从原文开头开始 | 老师 |
| **12** | **A1- 必须保留原文中的关键人名** | **本项目新增** |

**仅警告**：⑬ 句子短于该级最短词数 · ⑭ 出现可能超纲的语法信号词 · ⑮ 某级三题答案字母全相同 ·
**⑯ 多义实词词形命中（本项目新增）** · **⑰ 原稿等级偏低（仅 news 模式，本项目新增）**

> **第 12 类的由来**：佳阳老师的方法论要求「A1- 关键人名必须保留，可写成 `Graves, a scientist`
> 这种形态（原名 + 同位语说明身份），不能泛化成 `A scientist`」，但原脚本对此**一行代码都没有**。
> 实测老师的示例文章：原脚本判定「✓ 通过」，加上这一类后立刻抓出 `Franklin` 和 `Graves` 两个人名丢失。

> **第 16 类**：只做**词形命中**（`POLYSEMY_WORDS`），只在 A1-/A2 提示，**不判语境** ——
> 语境判断属语义，交给裁判。清单**宁窄勿宽**，报太密就没人看了。

**裁判查的 9 类问题**（内容层，脚本查不了的）

`fact_added` · `fact_dropped` · `fact_altered` · `card_misaligned` · `bridge_broken` ·
`topic_word_weak` · `answer_unsupported` · `option_unfair` · **`ambiguous_word`**

其中 P0（自动修）= 前四项 + `answer_unsupported`；P1（只报告）= 其余。

## 这个项目要证明什么

上一代（V1）搭了 8 个工作流，效果**不如**裸模型 + 老师 skill。
诊断：**8 次串联 = 8 次信息损耗 + 0 次质量增益**，而且**没有 evals**。

所以本项目的证明目标不是"展示编排"，而是**展示裸模型给不了的增量**：

- **稳（A）** = 17 类确定性脚本校验，不靠模型更聪明，靠脚本挡掉不合格
- **门槛低（C）** = 老师上传原文即得成稿 + 质检报告，不用写 prompt、不用装环境

**实测证据**：新增的「A1- 人名保留」规则当场抓出 `Franklin` 和 `Graves` 两个人名丢失 ——
而老师原脚本在同一篇文章上判定「✓ 通过」。**脚本过了 ≠ 内容对。**

## 已知边界

- **本轮不做**：自适应难度调节（用户读着自动切级别）· 发布分发 · 账号权限 · 多维知识库
- **超纲词没有词表**：现在只有十几个语法信号词，**没有任何词汇表** → 超纲词基本没人管
- **没有「单卡词数」约束**：只卡单句上下限与整级总占比，**段落长度失控是盲区**
  （实测末卡爆掉：A1- 34 / A2 49 / B1 61 / B2+ 83 词）
- **裁判 v0 尚未做误报率实测**：需要拿真模型跑老师示例，对照人工金标准算漏报/误报
- **数据落盘依赖可写磁盘**：部署到无持久化存储的平台时，重启后数据会丢
  → **重新发布可能覆盖线上已生成的文章，发之前先备份**
- **原文等级不做校验**：按设计，`b2` 模式下等级由人工判定，系统不质疑
