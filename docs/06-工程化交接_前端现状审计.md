## 1. P0 阻塞项（交接前必须解决）

### P0-1　四把密钥以明文写在前端，线上任何人 F12 可见

实测：直接 `curl` 线上页面，以下字符串**全部原样出现在返回的 HTML 里**：

| 密钥 | 位置 | 状态 |
|---|---|---|
| SiliconFlow `sk-fsnx…qzu`（文生图 + LLM 共用） | `index.html:1289` | 🔴 已泄露 |
| Dify 主工作流 `app-RVTU8kMk…（已轮换）` | `index.html:2110` | 🔴 已泄露 |
| Dify 生成工作流 `app-SuBV84EA…（已轮换）` | `index.html:2111` | 🔴 已泄露 |
| Dify 事实抽取工作流 `app-9wWWiNpl…（已轮换）` | `index.html:2112` | 🔴 已泄露 |

**风险**：任何人拿到链接 → 查看源代码 → 盗刷 SiliconFlow 余额 / 打满 Dify 配额。同一把 SiliconFlow key 还同时被 `agent_reach_bridge.py` 复用，等于前后端共用一把。

**要求后端同事**：
1. **立刻轮换这 4 把密钥**（旧 key 视为已公开，不可继续使用）。
2. 所有第三方调用改为**服务端代理**，前端只调自己的 `/api/*`。
3. 密钥进环境变量 / 密钥管理，禁止进仓库。

### P0-2　业务数据全部存在浏览器 localStorage，换台电脑就空

| Key | 内容 |
|---|---|
| `wb_content_bank_v1` | 内容库文章（含封面 base64） |
| `wb_material_bank_v1` | 素材库 |
| `wb_publish_history_v1` | 发布记录 |
| `wb_feedback_data_v1` | 用户反馈 |
| `wb_taxonomy_v1` | 标签体系缓存 |

后果：**每个人打开的都是一个空系统**，A 生成的文章 B 看不到，也没有任何服务端备份。
附带问题：封面图以 base64 存 localStorage，512×512 约 0.55 MB/张，浏览器上限约 5 MB → **约 9 张就写满**，现有 `pruneCoverQuota()` 只是打补丁。

**要求**：换成真实数据库（文章/素材/发布/反馈四张主表），封面与音频改存对象存储，库里只存 URL。

### P0-3　五个功能依赖本机桥接层 `http://127.0.0.1:8787`

前端 `DEFAULT_API_BASE = "http://127.0.0.1:8787"`（`index.html:1955`），以下接口全部走它：

```
GET  /api/health          POST /api/trends        热点榜单
POST /api/scan            抓取原文（依赖本机 Chrome）
GET  /api/tags/taxonomy   POST /api/tags/extract  三层标签
POST /api/tts  /api/tts/batch   TTS 批量合成
GET  /api/library         GET /api/source-health
```

**别人打开你的链接，这几项 100% 失败**（除非对方电脑上恰好也跑着这份 bridge 且是同一台机器）。

### P0-4　抓取原文依赖「本机安装的 Chrome 图形程序」，服务器上根本不存在

`agent_reach_bridge.py` 写死了：

```python
chrome = "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"
```

并且还有一条"复用用户手动开的 CDP 9222 调试 Chrome"的兜底路径。这两条在 Linux 服务器 / 容器里**都不成立**。

**要求**：服务端抓取改用 Playwright 官方 Docker 镜像（`mcr.microsoft.com/playwright/python`）自带的 Chromium，或退一步改用 RSS / 官方 API 源，不要继承这条本机路径。

## 2. P1 重要项（影响工程质量与可维护性）

| # | 问题 | 说明 | 建议 |
|---|---|---|---|
| 5 | **零鉴权** | `doLogin()` 只是选角色写 `state.user = {role, name}`，无密码无 token；`canOperate()` 纯前端判断 | 改真实登录 + JWT，权限在服务端二次校验 |
| 6 | **单文件 694 KB** | HTML/CSS/JS 全在一个文件，无构建、无模块、无测试、无 lint | 拆 Vite + 组件化；至少先按功能域切 ES module |
| 7 | **Dify 输出 schema 双轨** | 通过分支返回 `sens_level`，排除分支返回 `sensitive_level` + `status:"exclude"`（不是 `excluded`）。前端靠 `isExcludedStatus()` 等兼容函数兜住 | **在 Dify 工作流侧统一输出字段**，否则后端同事会第二次踩坑（这一处曾导致整条生产链静默卡死） |
| 8 | **音频 240 MB 在本地目录** | `backend/audio/` 240 MB，由 bridge 以相对路径托管，前端拼成 `http://127.0.0.1:8787/...` | 迁对象存储 + CDN；源码注释里已自述"正式推送前需迁移" |
| 9 | **无日志 / 监控 / 告警** | 后端有 `/api/errors` 但只在本地内存 | 接集中日志 + 关键链路埋点 |
| 10 | **仓库脏** | `backend/` 下有 `.article_cache.json.tmp`、`library.json.tmp`、`__pycache__`、`.DS_Store`；`output/` 下有 `frontend_v2/`、`frontend_original_index_2026-09-03.html`、14 MB 历史 zip | 交接前清理，否则分不清哪个是真源 |

## 3. P2 优化项

- `hotspots.json`（89 KB）已**零引用**，是死资产。
- `frontend/covers/` 13 MB 老封面图随部署一起上传，拖慢发布。
- 双语文案全部内联在函数里（`L("中文","English")`），宜抽 i18n 资源文件。
- 前端直连第三方 API 存在 CORS 与速率限制风险；Dify Cloud 免费额度有限，压测前先确认配额。
- 无分页/无并发保护：素材抓取与 TTS 批量都是前端直接打，用户多点几次就打满。

## 4. 回答三个关键问题

### Q1：现在把这个链接发给别人，能真的用起来吗？

**部分能用，但只能演示一半。**

- ✅ **能用**：全部 UI 交互、Dify 文章生成、事实抽取、封面生成 —— 因为这些都是前端**直连云端 API**，只要 key 有效，谁打开都能真跑。
- ❌ **不能用**：热点抓取、原文抓取、三层标签提取、TTS 合成与音频播放 —— 全部依赖你本机 8787 桥接层。
- ❌ **数据不同步**：各人各存各的 localStorage，互相看不见。

> ⚠️ 附带代价：只要把这个链接发出去，等于同时把 4 把密钥公开。**建议先轮换密钥再考虑分享。**

### Q2：是不是必须本地电脑接一个后端？

**是的，完整的"能同步、能共享"的版本必须有服务端。** 但分两层看：

- 纯 UI + Dify 链路：**不需要**，云端 API 已直连。
- 数据同步 / 素材抓取 / TTS / 多用户协作：**必须**，且服务端还要能跑 headless 浏览器。

### Q3：能不能部署到某个地方让其他人都能看到？

有三个可选路径，按投入排序：

| 方案 | 投入 | 能做到 | 不能做到 |
|---|---|---|---|
| **A. Serverless 代理（最快）** | 1–2 天 | 前端上 Vercel/Netlify/Cloudflare Pages；密钥进环境变量；Dify + 封面全员可用 | 数据仍各存各的；抓取/TTS 仍缺 |
| **B. 正式工程化（推荐）** | 1–2 周 | 前端 + 后端服务 + 数据库 + 对象存储 + 队列；全员共享同一份数据；抓取/TTS 服务端化 | — |
| **C. 内网临时版** | 半天 | 后端同事 `docker compose` 起服务，nginx 托管前端，把 `DEFAULT_API_BASE` 改成 `""`（同域） | 仅内网可见，外网访问不到 |

**推荐走 B，A 作为过渡**。方案 B 的目标架构：

```
前端（Vite 构建，静态托管）
        │  同源 /api
        ▼
后端服务（FastAPI 或 Node）
   ├── 代理 Dify 三个工作流（密钥在服务端）
   ├── 代理 SiliconFlow（封面 / LLM / TTS）
   ├── Playwright 容器负责原文抓取
   ├── 数据库：文章 / 素材 / 发布 / 反馈 / 用户
   └── 对象存储：封面图 + 音频（CDN URL）
```
