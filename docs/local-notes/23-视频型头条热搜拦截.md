# 23 · 视频型头条热搜拦截（不纳入热点列表）

日期：2026-09-14
改动文件：`backend/agent_reach_bridge.py`
commit：`ba98699c48c7`（远端 sha `6443ff2e6607`）

---

## 1. 背景：为什么还有「无原文」

2026-09-14 线上整榜复拉，头条 10 条里仍有 3 条 `no_source`。逐条解剖话题页「事件详情」块后确认：
**不是抓取失败，是这类事件根本没有文章正文。**

| 热搜 | 块内有什么 | 文案长度 |
|---|---|---|
| 卫健委：要引导抵制不正确婚育观 | 仅 `/video/7685220019508084745`，无 `/article/`、无 `/w/` | 56 字 |
| 俄罗斯军列满载新坦克运往前线 | 仅 `/video/7685227075326148658` | 111 字 |
| 50岁女子坚持锻炼练出6块腹肌 | 仅 `/video/7685227254221111334` | 70 字 |

文案形态为 `00:12 国家卫生健康委：…… 证券时报e公司 32 2小时前` —— 带时长前缀的视频简介。

### 抢救尝试（已确认无解）

抓 `/video/<id>` 页（35–36KB）与移动端 JSON：

- `extract_article_from_dom` = **0 字**
- `meta-description` / `description` = 视频标题 + 样板文（「…于 2026-09-14 发布在今日头条，已经收获了 838 个喜欢」）

→ 视频型**全链路无文章正文**，换 URL 救不回来。

### 为什么文案不当正文用

`_TT_MIN_TEXT = 125` 是故意挡的：短视频文案实测 56–119 字，最短真实简讯 133 字，中间有干净空隙。
把视频简介喂进事实抽取会产出垃圾事实。

---

## 2. 决策

Bryan：「如果是短视频的，就拦截了，就先不纳入热点搜集里了。」

即：**视频型 → 整条从热点列表剔除**，不再以「无原文」形态出现。

---

## 3. 改动（6 处原子替换，全部命中）

| # | 位置 | 改动 |
|---|---|---|
| ① | `_TT_MIN_TEXT` 之后 | 新增开关 `TOUTIAO_DROP_VIDEO = True` + 台账 `_TT_DROPPED_VIDEO` + `tt_take_dropped_video()` |
| ② | A1 直达文章成功分支 | 记 `row["tt_kind"] = "article"` |
| ③ | A2a SSR 分支 | 记 `row["tt_kind"] = sr["kind"]`；`kind=="video"` 且开关开 → 标 `video_dropped` 并**提前 return** |
| ④ | A2b 渲染兜底成功分支 | 记 `tt_kind = "article"` |
| ⑤ | `fetch_toutiao` | `video_dropped` 条目入台账后 `continue`，不入结果列表 |
| ⑥ | `/api/trends` | 响应新增 `filtered_video`（本批被拦截清单，说明条数变少是预期） |

### 两个刻意的设计选择

1. **不写错误日志、不置 `degraded`。**
   `_is_real_degradation()` 对任何非渲染类错误都返回 True。若为拦截记 warn，会让整榜挂上
   「部分信源未抓到」横幅——误导。主动筛选不是降级，故走 `filtered_video` 台账回传。

2. **拦截条目不进 `_health_record`。**
   源成功率要反映「交付出去的内容质量」，被主动筛掉的条目不该把成功率拉低。
   故 `continue` 在 `_health_record` **之前**。

3. **提前 return 的副作用（正向）**：跳过该条的「中文源兜底」与无头渲染尝试，
   整榜耗时 68.5s → 17.6s，并消掉此前 5 条误导性渲染告警。

断言：结果列表无 `video_dropped` 条目、无 `tt_kind=="video"` 条目；台账取出后清空。**通过**。

### 端到端（本地 `/api/trends?theme=all`）

- `filtered_video` 字段存在，含 6 条，标题与单元级一致
- 交付头条 6 条：`ok 3 / short 3`，**零 `no_source`**
- `degraded=False`、`errors=[]`
- `tt_kind` 全部为 `article`/`micro`，`video` 残留 0

### 连带观察

按源分布：头条 6 / CGTN 7 / Variety 4 / NPR 4 / Billboard 4 / Global 4 / Live Science 1 = 30。
被筛掉的 3 条中文热点腾出的槽位由国际源补上 → **中文占比 15/30 → 13/30**。
若后续觉得中文偏少，可调 `fetch_trends` 的 `limit` 或 `PER_SOURCE_LIMIT`，与本次改动无关。

## 5. 回退方式

把 `TOUTIAO_DROP_VIDEO` 置 `False` 即恢复旧行为（保留条目、如实标记 `no_source`），无需改其他代码。

## 6. 线上核验（三次调用，含一次绕过缓存的重跑）

| 次序 | 耗时 | filtered_video | 头条 no_source | degraded | errors |
|---|---|---|---|---|---|
| 第 1 次（部署后首调） | 36.2s | 6 | 0 | **True** | 1 条 warn |
| 第 2 次（5 分钟内） | 3.2s | 6 | 0 | False | 0 |
| 第 3 次（等 5 分钟绕过 fetch 缓存，真实跑一轮） | 25.1s | 6 | 0 | False | 0 |

**第 1 次的 `degraded=True` 是容器冷启动的一次性产物，不是本次改动引入。**

告警内容：`cache.translation.load: [Errno 2] No such file or directory: '/app/backend/.toutiao_en_cache.json'`。
根因：翻译缓存文件落在容器内 `/app/backend/`，**部署重建容器即丢失**，首个批次读不到 → 记 warn；
该批次结束后 `_save_tr_cache()` 把文件写回，后续批次不再告警。

代码层面的不一致（未改）：`_load_tr_cache()` 对「文件不存在」也告警，而同文件的
`_load_tag_cache()` 明确写了「冷启动属正常情况，不该每次都告警」。两处对齐即可让首次调用也干净。

副作用提示：`_is_real_degradation()` 对任何非渲染类错误都返回 True，所以这一次 warn 会让首屏
出现「部分信源未抓到，结果可能少于实际」横幅 —— 实际 0 个源失败。属**既有**行为，与本次拦截无关。
