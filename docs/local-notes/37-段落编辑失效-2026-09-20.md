# 段落编辑「白改」事故：编辑能改字，但改完没人知道

> 2026-09-20 · Bryan 报告：「文章分段核对的过程中，理论上是支持编辑的，但是我编辑修改后，
> 推送给人工审核的版本，是没有变化的，等于这个编辑没用。」
> 结论：**真 bug，且是四层全丢**。已修复上线。

---

## 1. 结论先写

段落正文用的是浏览器原生 `contenteditable` —— **敲键盘就能改字，所以「看起来改成功了」**。
但把改动「收下来」的回调 `paraEdit(el)` 从第一行就取错了属性，函数第二行静默 `return`。

于是这四个地方**全都是原文**：

| 落点 | 修复前 | 修复后 |
|---|---|---|
| 内存生成稿 `GEN[k].paras[i]` | 原文 | 编辑后 |
| 本机草稿 `wb_para_draft_v1`（防误刷新） | **根本没落盘** | 编辑后 |
| 「存入文章库」的 `paras` / `articles` | 原文 | 编辑后 |
| 逐段审核页（审核老师看的版本） | 原文 | 编辑后 |

而且**全程零报错**：console 干净、没有任何 toast。

---

## 2. 根因：属性宿主错位

渲染段落卡片的 `paraCard()` 把定位属性挂在**卡片**上：

```html
<div class="pcard" data-k="A1" data-i="0">          <!-- ← 属性在这里 -->
  <div class="pbody" contenteditable="true"
       oninput="paraEdit(this)">…</div>              <!-- ← this 是这里 -->
</div>
```

而回调收到的 `this` 是 `.pbody`：

```js
function paraEdit(el){
  const k = el.getAttribute("data-k"), i = +el.getAttribute("data-i");   // ← 恒为 null / NaN
  const g = GEN[k]; if(!g || !g.paras || !g.paras[i]) return;            // ← 静默 return
```

`GEN[null]` 是 `undefined` → 第二行直接返回。**改动从未被记录过。**

### 为什么特别难发现

1. **`contenteditable` 是浏览器原生行为** —— 文字确实变了，肉眼完全看不出异常；
2. **段落词数徽标确实会刷新**（那行用的是 `el.closest(".pcard")`，写对了）；
   连「3 词」都跟着变，用户更加确信改成功了；
3. **不报错、不提示** —— 没有 console 日志，没有 toast；
4. **只有走到下游才暴露** —— 切到审核页、或存进文章库，才看到还是原文。

---

## 3. 实测复现（修复前）

CDP 真实 DOM：注入生成稿 → 进入段落校对页 → 在 contenteditable 里输入 → 读四处：

```
cardDataK            : "A1"          ← 属性确实在卡片上
bodyDataK            : null          ← 正文上没有，这就是成因
genAfterEdit         : ["ORIGINAL-A1-p1"]   ← 内存没变
draftExists          : false                ← 草稿没落盘
reviewShowsEdited    : false
reviewShowsOriginal  : true                 ← 审核页显示原文
bankParasA2          : ["ORIGINAL-A2-p1","ORIGINAL-A2-p2"]
```

---

## 4. 修复

`frontend/index.html`

1. **`paraEdit()` 改从卡片取属性**：`el.closest(".pcard")` → 读 `data-k` / `data-i`；
   顺手把重复的 `closest` 去掉（原来词数那行又找了一次卡片）。
2. **失败不再静默**：取不到卡片/档位/段落时 → `console.error` + toast
   「这段修改没有被记录：页面状态异常，请刷新后重试」。
   > 判据：**编辑类回调「落到哪」必须有断言，取不到宁可报错也不能静默返回。**
   > 这类静默失败的代价是「用户以为改好了」，比报错严重得多。
3. `paraCard()` 加注释标注属性归属，防止后人再从 `.pbody` 读。

## 6. 防再犯

1. **回归探针进仓库**（`tools/probe_para_edit.mjs`），改任何编辑类回调后必跑。
2. **技能补坑位**（`readpal-frontend`）：编辑类回调的定位属性在卡片上、不在正文上；
   编辑后必须验证「内存 / 草稿 / 入库 / 审核」四处，只看界面文字不算验证通过。
3. 判据写死：**「编辑功能好不好使」永远不能用眼睛看输入框里的字来判定。**

## 7. 本次没动、但要知道的

- **草稿恢复的时机**：`restoreParaDraft()` 在 `applyLive()` 末尾调用。
  误刷新后草稿还在（localStorage），但要**重跑一次同一素材**才会合并回生成稿
  （指纹不一致就不合并，防止串到别的素材上）。页面文案「误刷新不会丢」指的就是「草稿在」。
- **跨设备/跨账号**：靠「存入文章库」→ `POST /api/library` → 后端 `library_upsert()` 整对象落盘
  （含 `paras` / `articles`）。前端修好后，同步过去的就是编辑后的版本。
- **`s10`（人工校对）是死代码** —— 不在 `fns` 里，永远不会渲染；
  实际可编辑的页面只有 **idx 9 段落校对**，审核页 idx 10 是只读。
  本次未删（不在本次范围），但改这块时不要以为有两个可编辑页面。
