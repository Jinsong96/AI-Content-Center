### Google News 为什么"只到线索级"（两条独立证据）
1. **跳转链解不出原文**：链接形如 `news.google.com/rss/articles/CBMi…?oc=5`。
   base64 解码成功（179 字节），但**载荷内不含任何 URL**（`urls_inside=NONE`）。
2. **后端也跟随不了**：把跳转链丢给 `/api/scan`，返回的 topic 就是 URL 本身，
   错误为「未能解析为 RSS/Atom，已降级为网页标题」→ 说明拿到的是 **JS 壳，连 `<title>` 都没有**。

→ **Google News RSS 给不了原文链接、也给不了正文。**
→ 而 Bryan 要求「选中必须能直接生产」。**所以它不能作为检索主链路。**

**推论（这是方案的前提）**：检索服务必须**返回真实发布方 URL**（+ 最好能给正文）。

### 8.3 附带修掉的一个静默失败

**现象**：趋势扫描进行中，老师自己贴的来源卡片会**每秒消失一次**（`state` 里还在，界面上没了）。

**根因**：`scanTimer` 每秒调一次 `renderHots()`，而「扫描中」分支每次都把 `#hotgrid`
重置成「正在全网扫描…」占位符 —— 只该占住全网热点那一块，却把自定义条目一起清了。

**修法**：该分支保留自定义卡片（`renderCustomHots(g, true)` 立即出卡），
并给卡片渲染加**幂等 stamp**，防止每秒重复追加一批。

## 8.6 「无原文」条目一律不进列表（2026-09-14 · 用户实测反馈后修）

**用户反馈**：热点搜索仍出现「无原文」，实例是「中国有1.26亿只"毛孩子"」
（`toutiao.com/trending/7685150835596656646`，视频聚合页）。要求**所有无原文的都拦截，不出现在热点搜索后的页面**。

**为什么之前会漏**：后端只拦了「视频型」这一种特例（`TOUTIAO_DROP_VIDEO`），而这条恰好没被识别成视频 ——
`_tt_event_block` 没解出「事件详情」块 → `kind="none"` → A2b 无头渲染（线上容器无 Chrome 会跳过）→
B 中文源兜底失败 → C 诚实降级成 `no_source`。
**结论：「视频型」是特例判定，覆盖不全；要按「有没有可用正文」统一收口。**

**修法**：
- 后端新增 `MIN_USABLE_TEXT = 200`，`fetch_trends` 在 `enrich_fulltext` **之后**、翻译**之前**统一筛。
  位置很关键：必须在补正文之后（否则 RSS 条目还没正文就被判死），在翻译之前（省掉给即将丢弃的条目做中英互译）。
- 前端同名常量 + `renderHots` / `renderCustomHots` 双双过滤（兜底，覆盖 `/api/scan` 与将来的检索接口）。
- 判据必须与前端 `hasUsableText` **严格一致** —— 那是生成流程的真闸门。

**顺手修掉一个被这次改动引爆的隐患**：`state.realHots = []` 时原先会 fallthrough 到 `HOTS` 分支，
显示 **20 条 2026 年 8 月的内置演示新闻**，冒充「本次抓取结果」。过滤生效后这个漏洞被触发的概率大幅上升
（某个主题全被过滤就中招）。改为 `realHots` 非 null 即进真实分支，空则显示空态 + 原因。

**「隐藏了多少条」必须说出来**：热搜榜 50 条、界面 27 条，若没有解释就像抓取坏了。
- `/api/trends` 新增 `filtered_no_text` 台账（含 title / url / status / len / lang）
- 前端横幅：「已隐藏 8 条无可用原文的热点，其中 5 条是视频型事件。…」
- 自定义源扫描：`customScanNote` 与 toast 都带上被隐藏条数
