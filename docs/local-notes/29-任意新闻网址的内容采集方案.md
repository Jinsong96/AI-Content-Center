# 29 · 任意新闻网址的内容采集方案

- 日期：2026-09-14
- 状态：**方案待拍板，未开工**
- 起因：Bryan 加了 `https://abcnews.com/`，抓不出来（卡片显示「原文偏短 · 原文 165 字符」）。
  诉求：**所有新闻网址都能做热点搜集或原文采集**，不限于 RSS。
- 关联：`docs/24`（自定义信源可行性）、`docs/28`（定制热点方案与核验）

---

## 0. 结论先行

1. **这不是 ABC 的问题，是「发现」这一层的能力缺口。** 后端只会两招：把 URL 当 feed 解析 → 读 HTML 里的
   `<link rel="alternate">`。SPA 大站（ABC、ESPN）首页里**一条 feed 标签都没有**，两招必然全空。
2. **失败后的兜底是错的**：现在会「降级成网页标题」，于是产出一条以 URL/站点名当标题、正文 165 字符的
   **伪素材**。按刚定的原则（热点搜集服务于文章生产），这种条目**根本不该产出**。
3. **解法是一条约 6 级的降级发现链**，任何 URL 都能落到其中一级；并且**加入 `robots.txt → sitemap` 这条
   零猜测路径** —— 实测这是覆盖 SPA 大站最有效的一招。
4. 实测 ABC：官方 feed 25 条可用、`robots.txt` 声明的 news sitemap 有 **1000 条最新文章 URL**、
   文章页正文抽取 **5/6 命中**（824–5051 字符）。**ABC 完全可采，只是我们没去发现。**
5. 不承诺 100%：反爬站（AP 403、Reddit 403）**明确告知不支持**，不造假、不静默。

## 1. 根因（线上实测复现）

```
GET /api/scan?urls=https://abcnews.com/
→ ok=True  items=1  degraded=True
  topic     = "https://abcnews.com/"     ← 连标题都没取到，退化成 URL 本身
  ft_status = "short"  ft_len = 165
  errors    = [ scan.degraded_to_title: "未能解析为 RSS/Atom，已降级为网页标题（内容较单薄）" ]
```

**这条就是截图里的那条。** 链路：

| 步骤 | 发生的事 | 结果 |
|---|---|---|
| 1 | `fetch("https://abcnews.com/")` | 200，805KB HTML（React SPA） |
| 2 | `parse_feed(data)` | 不是 feed，失败 |
| 3 | `discover_rss(data, u)` | 首页 HTML 里 **0 个** `<link rel="alternate">` → 返回 None |
| 4 | 兜底：正则取 `<title>` | SPA 的 title 带 `data-react-helmet` 属性，匹配异常 → 退化成 URL |
| 5 | `enrich_fulltext` 抓同 URL 正文 | 首页碎片文本 165 字符 |

**关键判断**：第 3 步失败是**必然**的（SPA 用 JS 渲染，feed 链接不在 HTML 里）；
第 4 步的兜底**本身就是设计错误** —— 它把「发现失败」包装成「有一条内容」。

## 2. 老师填的一个 URL，其实有四种语义

现在代码只认第 1 种，其余三种全靠「降级」，于是全军覆没：

| 老师填的 | 语义 | 现状 | 应有行为 |
|---|---|---|---|
| `…/abcnews/topstories` | **订阅地址**（RSS/Atom） | ✅ 解析出列表 | ✅ 保持 |
| `https://abcnews.com/` | **站点首页** | ❌ 降级成 1 条伪素材 | 发现 → 得文章列表 |
| `…/International` | **栏目/专题页** | ❌ 降级成 1 条伪素材 | 发现 → 得该栏目的列表 |
| `…/xxx/story?id=136371711` | **单篇文章** | ⚠️ 半可用（标题取自 `<title>`，带站名后缀） | 直接当 1 条素材采集 |

**识别方法（不用 LLM，纯结构特征，成本 ~0）：**

```
① 解析成功 → 订阅地址
② HTML 且 og:type == "article" 或无 og:type 但有 <article> + 发布时间 → 单篇文章
③ HTML 且 og:type == "website" 或同域链接 > N → 列表页（首页/栏目）
④ 都不是 → 报告「不支持这个地址」，不产出任何条目
```

实测验证：ABC 首页 `og:type = website` ✅；ABC 文章页可正常抽正文 ✅。判据可用。

## 3. 发现链（L0 → L5，成本递增，命中即止）

| 级别 | 手段 | 实测命中 | 额外请求 | 备注 |
|---|---|---|---|---|
| **L0** | URL 本身当 feed 解析 | ✅ 已有 | 0 | 老师填对时最快 |
| **L1** | HTML `<link rel="alternate">` 自动发现 | ⚠️ NPR(6 个) / The Verge / ScienceDaily 命中；**ABC=0、ESPN=0** | 0（复用 L0 的 HTML） | **现有实现有 3 个 bug，见下** |
| **L2** | 常见路径探测 | ❌ ABC 全 404；WordPress 类站有效 | +6~10 | `/rss` `/feed` `/feed.xml` `/rss.xml` `/atom.xml` `/index.xml` `/.rss` `?feed=rss2` |
| **L3** | **站点知识库**（host → 已知 feed 路径） | ✅ 可救 ABC / ESPN | 0 网络 | ABC 在 `/abcnews/topstories`、ESPN 在 `/espn/rss/news` —— **都不在常见路径里，必须预置** |
| **L4** | **`robots.txt` → Sitemap → news sitemap** | ✅ **本次最大发现** | +2 | 见下 |
| **L5** | 列表页抽文章链接 → 逐篇抓正文 | ✅ ABC 首页 SSR 输出含 **272 个**疑似文章链接 | +1 +M | 最后兜底；站点改版会失效 |

### L1 现有的 3 个 bug（都要修）

```python
# discover_rss() 现状
if "alternate" in rel.group(1) and ("rss" in tag or "atom" in tag or "feed" in tag):
    url = href.group(1)
    if url.startswith("//"):   url = "https:" + url
    elif url.startswith("/"):  url = urljoin(base_url, url)
    return url                 # ← 只返回第一个匹配
```

1. **只返回第一个匹配** —— 第一个可能是评论 feed，不是主 feed。
2. **相对路径只处理 `/` 开头** —— `href="feed.xml"`（无前导斜杠）会原样返回 → 抓取失败。**漏掉一整类站点。**
3. **强制要求 rel 含 `alternate`** —— 有些站写 `rel="feed"` 或直接 `<a href="/rss">`。

### L4 为什么是最有价值的一招（实测）

`robots.txt` 是**标准约定**，站点会主动声明自己的 sitemap 位置 —— **零猜测**：

```
https://abcnews.com/robots.txt        → Sitemap: https://abcnews.com/xmap
                                                 https://abcnews.com/xmlLatestStories      ← news sitemap
                                                 https://abcnews.com/xmlLatestVideos
https://www.espn.com/robots.txt       → /sitemap.xml
https://www.sciencedaily.com/robots.txt → /sitemap-index.xml（33 个子 sitemap，.gz 需解压）
https://www.theverge.com/robots.txt   → /sitemaps/google_news
```

实测 `https://abcnews.com/xmlLatestStories`：**892KB、1000 条最新文章 URL**，带 `news:` namespace（含发布时间）。
=> **一个 SPA 大站，靠 robots.txt 一条请求就拿到了 1000 条最新文章。** 这是覆盖率的质变。

**代价**：news sitemap 只给 URL，**不给标题和摘要** → 要标题必须逐篇抓（见 §5 成本）。

## 4. 单篇原文采集（老师直接贴文章链接）

现状**已经可用**，实测 ABC feed 前 6 篇：

| 结果 | 条数 | 长度 |
|---|---|---|
| `ok` | **5/6** | 3161 / 2746 / 824 / 5051 / 5023 字符 |
| `failed` | 1/6 | `LIVE: ABC News Live` 直播页（**本就无正文，就该被拦**） |

要改两处：

1. **标题取 `og:title` 或 `<h1>`，不要取 `<title>`** —— 后者常带「| ABC News」这类站名后缀。
2. **取消「降级成网页标题」这条路径**（见 §1）。发现不出东西就是发现不出，明确报告，不产出伪素材。

## 5. 成本与缓存（决定要不要做 L4/L5）

实测一次完整发现：**首页 → robots → sitemap → 3 篇文章 = 6 请求 / 6.2 秒**。

| 环节 | 现状 | 方案 |
|---|---|---|
| 发现结果 | 每次扫描都重新猜 | 新增 `feed_index.json`：`host → {feed_url, sitemap, ts}`，**缓存 7 天**（含失败结果，避免反复重试） |
| 正文 | ✅ 已有 `article_cache`（51 篇 / 232KB） | 沿用 |
| 扫描期补正文 | `SCAN_ENRICH_LIMIT=12` / `TIMEOUT=10` | 沿用；L5 抽链后条数会变多，**必须先截断再抓** |

> ⚠️ **最坏等待** = `ceil(条数 / workers) × timeout`。L4 拿到 1000 条时**绝不能全抓** ——
> 只取前 N 条（建议 N=20，与 `SCAN_PER_SOURCE_LIMIT` 一致）。发现是廉价的，抓正文才是贵的。

## 6. 界面：三种明确状态（不许静默失败）

| 状态 | 文案 | 后续动作 |
|---|---|---|
| ✅ 发现成功 | 「已发现订阅地址，抓到 N 条」 | 直接可点 |
| ✅ 单篇采集 | 「已采集这一篇 · 原文 X 字符」 | 直接可点 |
| ⚠️ 发现失败 | 「**没能从这个地址发现可用内容**。建议：① 试该站的 RSS 页；② 直接贴具体文章的链接」 | 给可操作建议 |
| ⛔ 反爬站 | 「该站拒绝服务器访问（403），暂不支持」 | 明确不承诺，别让老师反复试 |

**共同点**：不管哪条链产出，最终都要过 `MIN_USABLE_TEXT`（200），否则不进列表 —— 与 `docs/28 §8.6` 一致。

## 7. 与产品原则的一致性（本次新定）

> **热点搜集服务于文章生产，不为搜集而搜集。**

所以本次方案里有两处**主动放弃**，是设计不是妥协：

1. **「降级成网页标题」被删掉** —— 它能为任何 URL 产出「一条内容」，但那条内容生产不出文章。删。
2. **L4 拿到的 1000 条不全抓** —— 抓不完也用不上；取前 20 条、每条都能生成，才是有价值的覆盖。

## 9. 风险与不承诺

| 风险 | 影响 | 应对 |
|---|---|---|
| 反爬站（AP/Reuters 403） | 覆盖不到 | 明确告知不支持，不造假 |
| news sitemap 只有 URL、无标题 | L4 需要逐篇抓才能出标题 | 只取前 N 条；标题抓不到就用 URL 路径段兜底 |
| L5 依赖 HTML 结构 | 站点改版即失效 | 它是**最后**一级，L0–L4 已覆盖大部分 |
| 站点知识库需人工维护 | 新站要加 | 只预置 Top 20；其余靠 L1/L2/L4 自动发现 + 缓存自增长 |
| sitemap 巨大（892KB / 1000 条） | 解析慢、占内存 | 流式取前 N 条 `<loc>` 即停，不整棵解析 |

## 10. 需要拍板的三件事

1. **站点知识库（L3）要不要做？** 它是唯一带人工维护成本的部分，但也是覆盖 ABC/ESPN 这类大站的
   关键（它们的 feed 路径无法靠通用规则猜出来）。建议做，先预置 20 个。
2. **L4 只取前 N 条（建议 20）能接受吗？** sitemap 有 1000 条，全抓不现实；取前 20 条对应
   「热搜榜 50 条 → 界面 27 条」的既有产品口径。
3. **反爬站明确标「不支持」能接受吗？** 我的建议是接受 —— 比反复失败或造假诚实。

## 11.2 顺手修掉的四个 bug（都是本轮实测暴露的）

1. **`looks_like_article` 把 ScienceDaily 首页判成文章** —— 它自称 `og:type=article`（站点 SEO 标注不严谨）。
   试过用「链接密度」区分，**实测列表页 0.24~0.67 / 文章页 0.01~0.31 完全重叠，分不开**。
   最终用「**URL 路径段数**」：根路径/单段路径不可能是文章（`/` 0 段 vs `/releases/2026/09/xxx.htm` 4 段）。
2. **sitemap 兜底优先取了栏目页 sitemap** —— ABC 的 `robots.txt` 依次声明 `xmap` / `xmlLatestStories` /
   `xmlLatestVideos`，只有第二个是文章列表。改为按名字优先 `latest`/`news`。
   修前取到的是 `https://abcnews.com/`、`/Live/`、`/Nightline/` 这类栏目页。
3. **正文缓存缺 `title` 字段** —— 旧条目命中缓存后标题退化成 URL。改为「缺 title 视为未命中」，自愈重抓。
4. **前端横幅被内部 warn 误判** —— ABC 信源完全成功，却因某条视频页抽不到正文的 `article.fetch` warn
   被判 degraded，挂上「部分信源未抓到」。改为**以逐源报告为准**。

## 11.3 一个必须记住的设计决定

**单个源抓不到，绝不 `note_error`。**
`_is_real_degradation()` 对任何非渲染类错误都返回 True（只有 `render.*` + warn 被豁免），
所以在发现层记 error 会让老师**加一个反爬站就把整个热点榜挂上降级横幅**。
结果由 `sources` 报告承载并回传 —— 它比日志更有用，因为它直接到达使用者眼前。
