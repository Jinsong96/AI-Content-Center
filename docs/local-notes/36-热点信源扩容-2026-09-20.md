# 热点信源扩容 · 实施记录（2026-09-20）

> 起因：Bryan 提出「热点搜集内容太多不够、BBC / ABC 这些主流大站搜不到」，并问「换成 AI HOT 会不会更好」。
> 结论：**不换 AI HOT**（它每天只 11–15 条、只有 AI 一类，换过去是 3 类 → 1 类）。
> 真问题是**信源清单被误判**，修完条数涨 4.5 倍。

## 一、核查结论（三个都实测过，不是推断）

### 1. BBC / Guardian / NYT / ABC 这些站**一直是可用的**，从来没坏过

它们不在清单里，是因为 **2026-09-02 那次「源可用性实测」是在本机跑的** ——
本机直连这些站全部超时 → 被判定「源不可用」写进代码注释，从此再没加回来。

| 测试 | 结果 |
|---|---|
| 本机直连 BBC | **超时** ✗ |
| 本机走系统代理（127.0.0.1:7890）抓 BBC | **200 / 24KB / 1.0 秒** ✓ |
| **线上 Railway 容器直连 BBC / Guardian / NYT** | **全部 200**，正文 4759–9990 字符 ✓ |

**根因**：桥接层 `fetch()` 用 `ProxyHandler({})` **显式禁用一切代理**。
本机访问这些站需要代理 → 必然超时。线上（美国机房）直连即可，不需要代理。

> 🔴 **判据**：判断「某个源能不能用」**必须用线上探针**，不能拿本机结果下结论。
> ```bash
> curl "$LIVE/api/scan?urls=<url>&limit=4"      # 用线上服务当代理实测
> ```
> 反例同样成立：Reuters / AP 在线上是 **403**，本机反而是超时 —— 两边都可能不同。

### 2. 商业 / 成长 / 故事三个大类**从来没配过任何源**

改造前 17 个源里，**没有一个**的 theme 标签是 business / growth / story，
连 `CGTN · Business` 都被误标成了 `["world"]`。
→ 教研老师点这三个大类 = **永远空白页**。不是抓不到，是根本没去抓。

### 3. 界面只见 25 条

`/api/trends` 调 `fetch_trends(theme, sub)` **不传 limit** → 用默认 **30**，
而且 `ranked[:limit]` 截断发生在补正文**之前**（先截 30 再筛）→ 线上实测最终只剩 **25 条**。

## 四、顺带修掉的两个真问题（都是本次改动**放大**出来的既有缺陷）

### 1. `article.cache.save` 写入失败被当成「信源故障」

源从 17 扩到 52 后，补正文次数大增，线上 `article.cache.save` 开始**成批失败**
（Railway 容器磁盘写入受限），一次请求攒出 **15–16 条 warn** → `_is_real_degradation()` 判 True →
界面挂上「部分信源未抓到」。**而实测交付 114 条、一个源都没少** —— 纯误报。

→ 新增 `_BENIGN_WARN_SCOPES`（判据很窄：只有 **warn 级** + 明确写「不影响本次结果」的 scope 才进名单）。

### 2. 降级横幅把「翻译缺中文标题」说成「信源未抓到」

源一多，中英互译的偶发失败也变多（本轮 16/105），横幅却统一显示
「部分信源未抓到，结果可能少于实际」—— 把一个源都没坏的一批说成失败，是最容易让人误判的提示。

→ 前端按 `scope` 分述：源级失败才说「信源未抓到」，翻译失败说「N 条英文热点的中文标题暂缺（不影响原文与生成）」，
两者都不是则不挂全屏横幅。

## 六、附：AI HOT 评估结论（Bryan 原始问题）

AI HOT（aihot.virxact.com，数字生命卡兹克做的 AI 行业热点站）实测：

- 公开 API 免费、无需 token（`/api/public/items?mode=selected&take=N`，**必须带浏览器 UA**，否则 403）
- **精选 11–15 条/天**、全量约 50 条/天 —— **比现有 71 条更少**
- **题材 100% 是 AI 行业**（tip 37 / ai-products 14 / industry 11 / ai-models 10 / paper 4）
- 每条给 **119 字符摘要**；精选 76 条里过 200 闸门的仅 **1 条**
- 原文抓取实测（用 ReadPal 自己的抓取器）：`x.com` **0** / 公众号 **36** / Substack **0** /
  tomshardware 4362 / ithome 1246 —— 全量池 **73% 原文是 X 推文**，先天抓不到正文

**结论：不能替代**（3 类 → 1 类，114 条 → 15 条）。
可用之处只有两个：① 作为「科学」大类下的 AI 科普补充源；② 它的 168 信源地图可当信源发现清单。
