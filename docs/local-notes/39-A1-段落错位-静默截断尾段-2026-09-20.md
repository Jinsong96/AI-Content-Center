## 3. 根因链（每一环都有代码/实跑证据）

### 3.1 两套基准不同源
- `nodeGenA1` / `nodeGenA2` 引用 **`{{#nodeClean.gist#}}`** —— FACT 侧**固定 12 条**、去数字去专名的大意节拍。
- `nodeGenB1` / `nodeGenB2p` 引用 **`{{#nodeClean.facts_text#}}`** —— ≤12 张事实卡，不足时「相邻段可复用同一张卡」。

→ A1-/A2 与 B1/B2+ 从一开始就不是同一套内容坐标。

### 3.2 A1- 的额度是零余量，且「拆段」没被禁
- A1- 写作标尺：**每段约 12–20 词**、全篇硬区间 150–240 词、**12 段**。
- 12 × 20 = 240 = 全文硬上限 → **一点犯错余量都没有**。
- 提示词在【段数规则】下只写了「某段信息特别多时…**要精简压缩到区间内，绝不能因为信息多就把段落写超长**」——
  **只堵了「写超长」，没堵「拆成两段」。** 模型选了一条没被禁止的路。
- 更具体的一处缺口：提示词末尾有【必须自查的五条硬指标】= **① 正文字数 ② 每段句数 ③ 平均句长 ④ 词汇难度 ⑤ 语法复杂度**
  —— **「段数」不在其中**。段数只在【段数规则】里以陈述句出现过，从未进入模型的「写完必须逐条核对」清单。
  而 A1- 恰恰是唯一会被迫破段数的那一档。

### 3.3 聚合层无条件截断尾段（`nodeGenAgg`）
```js
const PARAS = { A1:[12,12], A2:[12,12], B1:[12,12], B2:[12,12] };
if (arr.length > wantHi) { cut = arr.length - wantHi; arr = arr.slice(0, wantHi); }
```
`slice(0, 12)` —— **砍掉的是末尾**，而末尾正是「信息来源」段。

### 3.4 这个告警从来没到过人眼前（静默失败）
截断会 push 进 `para_warn` → 最终进入 Dify 输出的 **`map_warn`** 字段。
但：

| 文件 | `map_warn` 出现次数 |
|---|---|
| `frontend/index.html` | **0** |
| `backend/agent_reach_bridge.py` | **0** |

`applyLive()` 读了 `articles_json / paras_json / words_json / levels_meta / fact_map / unused_facts / quiz_json / validation`，
**唯独没读 `map_warn`**。→ **段数截断、段数不足、生词表混入三类告警全部静默。**

### 3.5 校验层不设防
- `nodeValidate` 的 **10 项里没有「段落对齐」**，也没有段数校验。
- `nodeGenAgg` 里 4 档自报 map，注释明写：**「4 档体系：每组 1 档，无需组内统一」** → 不做跨档一致性检查。
- ⑨ 大意复核提示词明文：
  > 「低档（A1/A2）本来就只讲大意、更简略 —— **简略不算走样**」
  > 「`covered`… 低档覆盖不全**不算失败**，但必须如实报告」

### 3.6 前端渲染纯按索引对齐
`alignBodyHTML()`：`maxP = max(各档段数)`，逐行 `#i` 铺四档。
- **四档都是 12 段 → 行数相等 → 界面看起来「对齐了」**，只有逐段读内容才发现串位。
- 没有任何语义或映射层面的校验。

### 3.7 附带发现（独立 bug）
前端 `paraFactIds()` / `factCiteHTML()` / `factTraceHTML()` **一律按 `liveFacts()`（= facts）渲染**，
但 A1/A2 的映射编号是 **gist 序号**（`nodeAgg` 用 `basis:'gist'` 归一化到 `gist_count`）。
→ **A1-/A2 的「事实卡 N」标签是张冠李戴的**，悬停看到的英文不是编号对应的那条。
根因：前端**从未读取 `map_basis`**（出现 0 次）。

## 4. 修复方案（分三批，均未实施）

### 必修 1 · 堵住「拆段」（GEN 提示词 `nodeGenA1` / `nodeGenA2`）
在【段数规则】下补三条，并把「段数」补进【必须自查的硬指标】（五条 → 六条）：
1. **一条大意 = 一段，严格 1:1**；不得把一条大意拆成两段，也不得把两条大意并成一段。
2. 某条大意信息多时 **只保留主干、砍掉分支** —— 宁可少写一个细节，也不许拆段。
3. **写完先数**：大意 12 条 → 段落必须 12 段；**第 12 段（末条）不得缺席**。
4. 【必须自查的五条硬指标】末尾追加 **⑥ 段数必须为 12**，与 ① 正文字数并列（这两条一起决定 A1- 会不会爆）。

### 必修 2 · 把「静默截断」改成硬失败（`nodeGenAgg` + `nodeValidate`）
- `nodeGenAgg`：截断时把 `cut` 数量显式带进 `map_warn`（已有），并**不再把截断当常规操作** —— 至少升级成可判 fail 的信号。
- `nodeValidate` 新增第 11 项「**段落对齐**」（`total_checks` 10 → 11）：
  - A1/A2（gist 基准）：`gist_map` 必须严格等于 `[[1],[2],…,[12]]`，且段数 = 12；否则 fail，detail 写「第 X 段应讲第 X 条，实际讲 Y」。
  - B1/B2+（fact 基准）：`fact_map` 非空、单调不减、首段含 1、末段含 `fact_count`，且段数 = 12。
- 前端质检面板多显示这一项（已有面板结构，加一项）。

### 必修 3 · `map_warn` 必须显示（前端 `applyLive()`）
`state.mapWarn = o.map_warn`，在段落对齐页与质检面板顶部显示黄条。
**这是通用修复** —— 三类告警（截断 / 段数不足 / 生词表混入）目前全部不可见。

### 必修 4 · 修 A1/A2 溯源标签张冠李戴（前端 + `nodeGenAgg`）
- `nodeGenAgg` 增加输出 `gist_json`（gist 的 12 条英文），供 tooltip 用。
- 前端按 `map_basis` 分流：A1/A2 渲染「大意 N」+ gist 文本；B1/B2+ 保持「事实卡 N」。

### 可选 5 · 统一基准（结构性根治）
让 **4 档全部以 gist 的 12 条为段落骨架**，`facts` 退化为「高档细节补给池」。
需要 FACT 侧新增 `gist_fact_map`（每条 gist ↔ 若干 fact 卡）。
- 好处：档间天然对齐；`unused_facts` 审计变准；换风格重跑不会串位。
- 代价：FACT 图 + 4 档提示词 + 聚合层 + 前端全要动；会改变 B1/B2+ 的内容组织方式。
- 建议：**先做必修 1–4，观察 3–5 篇；仍偶发错位再上。**

## 5. 风险与边界

- **必修 1 的风险**：把「拆段」堵死后，模型可能改成「写超长」或「砍信息」。须与必修 2 同时上线，否则会从一种错位换成另一种不合格。
- **教研口径项（不由我拍板）**：A1-「12 段 × 每段 ≤20 词」是零余量约束，是本次问题的放大器。若要给余量，需教研同意调整每段词数上限 —— 段数 12 是 4 档一致的产品约定，不建议动。
- **A1/A2 的 gist 天生比 B1/B2+ 的 facts 粗**：即使修好对齐，低档仍会少细节（设计如此，不是缺陷）。
- **本次未触及**：句长/蓝思偏低（既有待办）、超纲率口径（上一批已改）。

### 7.3 实施中踩到的坑

1. **`sub_once` 幂等判据有反方向的坑**：若**新文案是旧文案的子串**（如「以旧文案开头再追加澄清句」），
   `new in txt` 恒真 → 静默跳过。永久护栏：`if new in txt and new != old and old not in txt`。
2. **闭包遮蔽**：`AGG_BASIS_NEW` 里重复声明 `const alignMap = {}`（块内遮蔽外层常量），
   且它位于 `if (fact_count > 0 || gist_count > 0)` 保护块内 → 外层导出空对象。
3. **`fact_map[g[0]] = raw_map[g[0]]`** 把刚统一的事实卡轴又覆盖回「按档位分叉」的口径 —— **只有实跑测试台才暴露**。
4. **测试数据构造陷阱**：14 张卡全标 `gist:1` → B1/B2+ 的 `align_map` 全被折成 `[1]`，
   看着像实现 bug，实为数据问题（但由此发现上面第 3 条真 bug）。
5. **`nodeEnd.outputs` 是 list（`{variable,value_selector}`）、code 节点 `outputs` 是 dict** ——
   `add_outputs()` 必须类型分流。
6. **`dify_run_app.py --out` 写的文件顶层就是 outputs 本身**（没有再套一层 `outputs`）——
   按 `d['outputs']` 读会误判「新字段全部缺失」。
7. **本机到 Railway 的网络**：curl 走代理 `CONNECT tunnel failed 502`、urllib 直连超时；
   **用 CDP 的 `Network.getResponseBody` 从已登录的 Chrome 里取原始响应体**才拿到真实线上 HTML。
