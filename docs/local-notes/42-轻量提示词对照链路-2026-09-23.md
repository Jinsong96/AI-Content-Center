```
【任务一 生成两档改编文章】
根据CEFR的分级标准和词汇标准，分别生成A1-和A2的文章。要求：
段落一致性：所有版本（含母稿）保持段落数和段落内容对齐，每段表达一个主要思想。段落切分根据内容和文章长度来，一般在8-12段都可以。
保证主要内容和文章关键词不变，比如主题词（哪怕超纲也不要变）、人名、地名等关键信息。
语言逐级简化：
  A2版本：保留原文主要信息，但语言更简单，句子更短，更易理解。
  A1版本：使用简单词汇、短句，降低语法复杂性，更适合基础读者。
句式调整：从B1到A2再到A1，句式逐渐从复合句转换为简单句。

【任务二 出题：三档各3道，共9道】
每篇难度的文章生成3道选择题（英文题干）和解析（中文）。三档都要出题：A1-、A2、B1。
主要从4个层面去出题，就是语言、文本、逻辑、认知。各档配额固定如下：
  A1-（语言2 + 文本1）：读者能不能认出词、读懂最直白的句子，这个阶段还谈不上推理和思考。
  A2（语言1 + 文本1 + 逻辑1）：开始加一道最简单的推理，但语言和字面理解还是主力。
  B1（文本1 + 逻辑1 + 认知1）：语言题基本取消——默认这个等级的词汇量够用了，不该再考单词。开始出现一道真正的认知题。

样例（供参考）：
  语言题：比如"clutterer"这个词在文中最接近哪个意思（选项给近义词）
  文本题：Sam Gosling是做什么的？（原文直接说了）
  逻辑题：以月饼那篇为例——"为什么便宜月饼卖得好，但商家反而赚得少？"（需要连起两句话才能推出因果，但线索都在原文里，不算难）

【输出格式】
只输出一个JSON对象，不要任何解释性文字、不要markdown代码块。
articles_json 是每档的整篇正文；paras_json 是同一篇按段落切好的数组（两者段数必须一致）。
quiz_json.levels 里 type 只能取 language / text / logic / cognitive 之一；answer 是正确选项在 options 里的下标（0-3）。
格式如下：
{ "articles_json": {"A1": "A1-整篇正文", "A2": "A2整篇正文"},
  "paras_json": {"A1": ["第1段", "第2段", "第3段"], "A2": ["第1段", "第2段", "第3段"]},
  "quiz_json": {"levels": {
    "A1": [{"type": "language", "q": "题目", "options": ["选项A","选项B","选项C","选项D"], "answer": 0, "explain": "中文解析"}],
    "A2": [...], "B1": [...] }} }
A1-、A2、B1 三档各写满 3 道题。
```

user：`【标题】{{title_in}}` + `【母稿正文】{{master_text}}` + 一句「按上述要求…只输出 JSON」。

### 关键设计决定（含理由）

1. **lite 复用 `state.lic` 与生成后的渲染页**，而非另起一套 —— 需求是「交互逻辑跟 CEFR 一样」，复用才不会走样。
2. **母稿（B1）由前端本地切段后注入 `data.outputs`**，再走 `applyLive()`。图 C 不返回母稿，避免为一件纯代码的事污染提示词。
3. **`expectedParaCount()` 用模型实际段数**（`state.live.licN = A1 段数`），不用默认 12 —— lite 的段数由模型按提示词决定，拿 12 当基准是假数据。
4. **AI 校验页必须显式说明**「本链路不做校验」—— 否则就是一个空白页。

## 六、首批实测结果（对照实验的原始数据）

两次真跑（同一段提示词，模型 `deepseek-v4-pro` / temp 0.45）：

| # | 母稿 | 产出字数 A1- / A2 | 平均句长 A1- / A2 / B1 | 段数 | 题目 |
|---|---|---|---|---|---|
| 1 | 380 词 · 10 段（城市养蜂） | **314 / 336** | — | 10 / 10 | 9 题 ✓ |
| 2 | 131 词 · 10 段（探针内置） | 128 / 131 | **9.8 / 10.9 / 10.9** | 10 / 10 / 10 | 9 题 ✓ |

对照产线规格（A1- 150 词 / 6–9 词每句；A2 240 词 / 10–13；B1 380 词 / 14–17）：

**稳的部分**
1. **段落对齐**：两跑都是段数与母稿一致、逐段对应。提示词里「段落一致性」那条被模型照做了。
2. **题目配额**：两跑都严格按「A1- 语言2+文本1 / A2 语言1+文本1+逻辑1 / B1 文本1+逻辑1+认知1」出题，
   英文题干 + 中文解析 + 4 选项齐全。**这是这版精简提示词里执行得最准的部分。**
3. **关键信息保留**：人名、地名、主题词没被简化掉。

**不稳的部分（都是提示词没约束到的）**
4. **字数完全不受控**：母稿 380 词时 A1- 出了 **314 词**（靶心 150，超 1 倍）；
   母稿 131 词时 A1- 只压到 128 词（几乎没压）。
   ⇒ **提示词里没有一个字数数字，模型就按「保留主要信息」的直觉走**，结果是「跟着母稿长度浮动」。
5. **逐级简化的方向对、幅度差一个档**：句长 A1- 9.8 vs B1 10.9，只差 1.1 词
   （规格要求 A1- 6–9 / B1 14–17）。读起来更像「A1 和 A2 是同一档的两种说法」。
6. **选择题答案位置不稳**：一次 9 题全部落在 0 号位，另一次不是 —— 模型自己的随机性，
   提示词没要求打乱选项。**要展示给人看的话，这一条得在前端或提示词里兜住。**

> 以上只是**两条样本**，还不能当结论。要用它回答「产线质量有多少来自提示词」，
> 必须**同一篇母稿两条链路各跑一遍**（本链路 vs CEFR文章分级），并且多跑几次。

## 七、产线约束剔除：lite 里不能有分级标准 / 校验标准 / 字数靶心（2026-09-23 补）

Bryan 口径：*「这个极简版本，只有这些提示词，原来所有的分级标准、检验标准和字数约束等都不对它起作用，都不需要有。」*

**核查方法**：不靠读代码下结论，逐页查 **真实渲染出来的 DOM**（生成完成态下用 CDP 逐页取元素）。

### 发现并修掉 4 处泄漏（第 1 处是功能性错误，不只是「显示不对」）

| # | 位置 | 症状 | 处理 |
|---|---|---|---|
| 1 | `s6()` 生成完成页 | **写作风格条还在**。点它 → `setStyle()` → `runGeneration()`，跑的是**四档产线主链路**（不是图 C）——对照组用户点一下就换掉了模型输出 | lite 下不渲染 `styleBarHTML()` |

### 为什么新增 `shownKeys()` 而不是写死 3

```js
function shownKeys(){
  if(!isLite()) return allKeys();                 /* 热点 / 自有 / 公版 / 授权母稿：恒 4 档，行为一字不改 */
  const ks = allKeys().filter(k => GEN[k] && GEN[k].paras && GEN[k].paras.length);
  return ks.length ? ks : allKeys();              /* 还没生成时仍给全档，避免空页 */
}
```

四条产线链路与 lite **共用同一批渲染函数**。写死 3 会连带把产线页面砍成 3 档。
探针里专门留了负向对照：`state.route="licensed"` 时 `shownKeys().length === 4` 且 `bigBarHTML()` 里仍有 `B2`。

### 有意不动的地方

- **段数 / 段落对齐**：这不是「字数约束」，而是**提示词自己写明的核心要求**（「所有版本保持段落数和段落内容对齐」）。
  lite 保留 3 档对齐视图与段落校对页，只把脚注从「AI 切分 + 人工校对」改成 lite 口径
  （母稿按原文段落原样保留，低档由模型按大意切分，需人工核对）。
- **`s7()` 校验页**：保留「本链路不做质量校验」的显式说明 —— 不能留成空白页。
- **`expectedParaCount()`**：仍取模型实际段数（`state.live.licN`），不落回默认 12。
