| 档 | 词数 | 占母稿 | 目标区间 | 结果 |
|---|---|---|---|---|

## 这一轮踩到并定死的五条（都是实测逼出来的）

1. **母稿切分必须由代码做，不能交给模型。**
   模型返回的 `b2_card_starts` 有两种坏法：① 个数 = 原文自然段数（5 段给 5 个锚点）；
   ② 给了 10 个但**不按原文顺序**（先列段级、再追加段内）。两轮提示词加压都改不动。
   现在：代码 `splitToCards()` 切好、当输入喂给模型（`master_cards`），B2+ 正文字段由
   parse 节点**硬取**，模型写的一律忽略。切分固定 10 张（超长 12 张），**不随段落数变**。

2. **改坏档位的成本 ≫ 修好档位的收益 ⇒ 回炉只重写没过的档。**
   「整篇重写」式回炉方差极大：同一档第 2 轮修好、第 3 轮又被改跑（实测 6 → 9 → 7 处）。
   现在页面算出 `fix_levels`（只点名有错误的档），连同一段由代码写死的「本轮只输出这几档」
   一起传给图；**没点名的档位模型根本碰不到**，回来后按档合并（`mergeCard`）。

3. **每档按「错误更少」留历史最优（`keepBest`）—— 交付必然不退化。**
   分母（母稿切分）跨轮一致，所以跨轮比档是安全的。这是纯代码保证，不靠模型自觉。
   探针断言：拼装后错误数**单调不增**。

4. **给模型的是「逐卡词数 + 约几句」，不是百分比。**
   实测模型算不动百分比，凭感觉写**总是超 20% 以上**（A1- 写到 45%、A2 63%、B1 88%）。
   现在代码把每卡预算算成绝对数并内缩到区间下半段（15%–65%），外加一行**绝对词数死线**。
   句数是先写死的、词数从句数长出来 —— 低级别写 6–9 词的短句，「顺手多写一句」就是超词数的主因。

5. **线上单服务托管必须显式开静态资源路由。**
   `card.html` 里是 `<script src="card_check.js">` 相对引用：本地整目录托管能命中，
   Railway 上只有 bridge 单服务 → `/card_check.js` 404 → **页面看着能开，但 `CardCheck` 是 undefined，
   整条质检链路静默失效**。已加 `_serve_card_check()`（路径写死，不接受外部拼接）。

## 改了什么

新增（都没碰 index.html / 老链路）：

| 文件 | 作用 |
|---|---|
| `frontend/card.html` | 卡片页单页（约 40KB）：填原文 → 生成（可中断/重试）→ 代码质检 → 逐卡对照 → 导出 docx |
| `frontend/card_check.js` | 工具包 `build_cards.py` 质检判据的浏览器端移植（100% 代码，零 AI） |
| `frontend/template.docx` | 导出用的版式模板（含 `DocTitle` / `DocLevel` 样式） |
| `tools/build_card_graph.py` | Dify App「ReadPal · 分级卡片」的图真源（4 节点：start → LLM → code → end） |
| `tools/probe_card_check.mjs` | 离线质检回归（32 项，含**页面↔探针同源守卫**） |
| `tools/probe_card_page.mjs` | 端到端回归（29 项：真跑图 + 渲染 + 导出） |
| `tools/probe_card_gen.mjs` | 生成侧诊断（不渲染，一轮 ~14s，调提示词时用） |

`backend/agent_reach_bridge.py` 加了三处：`/card`（托管单页）、`/card_check.js`、`/template.docx`，
以及 `card` 代理白名单（`DIFY_WF_CARD`）。

## 回归怎么跑

```bash
# 1) 离线质检（不联网，秒级）：32 项，含与页面逐字同源校验
node tools/probe_card_check.mjs

# 2) 端到端（本地静态服务 8899 + 真 Dify）：29 项
cd frontend && python3 -m http.server 8899 --bind 127.0.0.1 &
node tools/probe_card_page.mjs            # 跑线上：CARD_URL=https://.../card.html

# 3) 生成侧诊断（调提示词用）
ROUNDS=3 node tools/probe_card_gen.mjs
```

## 遗留 / 风险

- **提示词的温度降到 0.25**（原 0.45）换确定性；但仍偶发单档超上限，靠第 2 轮回炉收 —— 这是
  「不达标自动重跑」的既有策略，不是新问题。若哪天想再稳一档，可把 `MAX_ROUND` 提到 4。
- **`MAX_ROUND = 3`** 是时间/质量折中（每轮约 10–14s）。轮次记录、冻结/择优都能在页面上看见。
- 页面上仍在的告警（如 A1- 出现 `who` 之类可能超纲的词）**是给人看的提示，不是硬错误** ——
  工具包原判据如此，没有放宽也没有加严。
