# 26 · 自定义信源：用户需求分析与功能边界

日期：2026-09-14
视角：产品（需求层，不涉及实现）
前置：`docs/25-自定义信源改造方案-从填地址到选领域.md`

> **诚实声明**：本文中的「用户原话」是**基于场景推演**，**尚未做真实用户访谈**。
> 推演依据是两类岗位的职责与工作流，不是访谈记录。文末给出验证方式与建议验证的问题。

---

## 1. 用户是谁：两类人，需求不同

| 维度 | 教研老师 | 市场老师 |
|---|---|---|
| 核心任务 | 备课、找阅读素材、出练习 | 招生宣传、活动策划、品牌内容 |
| 使用频率 | **高**（每周固定课时） | 中（有活动时集中） |
| 触发点 | 教学单元主题（这周讲什么） | 政策动向 / 行业动态 |
| 判断标准 | 主题对不对、难度合不合适 | 来源权不权威、能不能引用 |
| 技术能力 | 会复制粘贴链接，**不懂任何技术概念** | 同左 |
| 情绪状态 | 忙、急，备课时不想折腾 | 要快，要能交差 |

**共同点**：都不会为了一个工具去学新概念。工具失败时，他们不会排查，只会放弃并找人。

---

## 2. 需求清单（细颗粒度）

### 场景 A · 备课找素材（教研，最高频）

| # | 用户原话（推演） | 真实需求 |
|---|---|---|
| A1 | 「这周讲环保，找篇素材」 | 按**主题**找内容，不想自己全网搜 |
| A2 | 「这篇太难了，学生看不懂」 | **难度要匹配**学生水平 |
| A3 | 「这篇靠谱吗，能上课用吗」 | 来源**可信**，不能是营销号/假新闻 |
| A4 | 「就一篇不够，我想挑挑」 | 要**多个候选**，不是只给一条 |
| A5 | 「我先看看原文再决定」 | 能**打开原文**确认，不能只有标题 |

### 场景 B · 追热点（两类人都用）

| # | 用户原话（推演） | 真实需求 |
|---|---|---|
| B1 | 「今天有什么大事」 | **时效性** |
| B2 | 「最好是跟教育有关的」 | **相关性**（不是娱乐八卦） |

→ **这两个需求已被主热点榜覆盖，不需要自定义信源承接。**

### 场景 C · 跟踪我常看的源（教研 + 市场）

| # | 用户原话（推演） | 真实需求 |
|---|---|---|
| C1 | 「我每天都看中国教育报 / Edutopia」 | 把**固定来源**汇聚到一处 |
| C2 | 「每次都要自己翻，很烦」 | **不用重复找**，记住我的偏好 |
| C3 | 「我只会复制网页地址」 | **不能要求理解订阅地址** |
| C4 | 「我贴了链接没反应，也不知道为啥」 | **失败要解释**，并且告诉我下一步 |

### 场景 D · 兴趣领域（教研，也是教学素材来源）

| # | 用户原话（推演） | 真实需求 |
|---|---|---|
| D1 | 「我们班男生爱看体育」 | 领域内容（体育/科技/文化） |
| D2 | 「但我不知道去哪找」 | **别让我自己找网址** |

### 场景 E · 市场老师的行业情报

| # | 用户原话（推演） | 真实需求 |
|---|---|---|
| E1 | 「教育部出新政策了吗」 | **政策动向**，要第一时间 |
| E2 | 「竞品最近在做什么」 | **行业动态** |
| E3 | 「这个来源能引用吗」 | **权威性** |

---

## 3. 需求 → 承接模块（关键取舍）

| 需求 | 由谁承接 | 理由 |
|---|---|---|
| A1–A5、D1–D2 | **领域频道**（平台维护源） | 高频、泛化，选源责任在平台 |
| B1–B2 | 主热点榜（已有，不动） | 已被解决 |
| C1–C4 | **自定义信源** | 个性化、低频、需要"记住" |
| E1–E3 | 行业/政策专题（领域频道的特例） | 来源固定，可预置 |

### 核心判断

> **「自定义信源」这个名字本身就是误导。** 用户要的不是"配置一个信源"，而是两件完全不同的事：
> **① 选领域就能看到内容** → 平台负责，最高频，占 ~80%
> **② 我常看的那几个源能记住** → 用户负责，但要**零门槛**

把这两件事混在一个"自定义信源"入口里，是目前设计的根本问题：
它逼着要做第①件事的老师，去完成第②件事的配置动作。

---

## 4. 功能定义

| 编号 | 功能 | 定位 | 承接需求 |
|---|---|---|---|
| F1 | **领域频道**（卡片墙，点一下出内容） | 主路径，覆盖 ~80% | A1–A5、D1–D2、E1–E3 |
| F2 | **添加我的来源**（粘贴链接，自动判断类型） | 辅路径，覆盖 ~20% | C1–C4 |
| F3 | **我的订阅**（保存过的一键使用） | 管理，让 F2 一次配置长期受益 | C2 |

**F2 的设计要求**：老师只做一个动作 —— **粘贴**。判断、适配、降级全部由平台完成。

---

## 5. 边界：明确不做什么

| 不做 | 理由 |
|---|---|
| **不做 RSS 阅读器**（未读标记、定时推送、全文缓存） | 老师要的是"找到能用的素材"，不是"管理订阅"；做了会把产品拖成资讯客户端 |
| **不承诺任意网站** | 明确支持清单：订阅源 / 新闻列表页 / 可桥接平台；其余明确告知并给替代 |
| **不支持需登录的内容**（微信公众号、付费墙） | 技术上拿不到，与其静默失败不如明确排除 |
| **不做内容生产**（投稿、评论、UGC） | 与本产品定位（素材获取）无关 |
| **不做无限量** | 每源设上限（建议 10–20 条），避免 2975 条这类情况淹没界面 |
| **不暴露技术参数** | 界面不出现 RSS / feed / 更新频率 / 抓取间隔 |

---

## 6. 优先级

| 级别 | 内容 | 判据 |
|---|---|---|
| **P0 必做** | F1 领域频道 + 能点进去用 + 失败有解释 | 高频 + 当前完全不可用 |
| **P1 该做** | F2 添加我的来源（粘贴即判断） | 覆盖长尾个性化需求 |
| **P2 可选** | F3 我的订阅管理 | 依赖 F2 成功后再做 |
| **P3 不做** | 见 §5 边界清单 | 明确拒绝，避免范围蔓延 |

---

## 7. 验证方式（需求尚未验证，这是风险）

上述需求是**推演**，不是访谈结论。建议：

- **找 2–3 位教研老师，各聊 15 分钟**。重点问**过去的行为**，不问意愿：
  - 「上一次备课找素材，你是从哪找到的？能演示一遍吗？」
  - 「最近一次你找到素材但觉得不能用，是为什么？」
  - 「你会把自己常看的网站发给同事吗？怎么发的？」（验证"固定来源"需求真伪）
- **观察而非追问**：让老师实际操作一次现有界面，看她卡在哪一步 —— 这比问她"你觉得好用吗"准确得多。
- 若访谈结果与本文不符，**以访谈为准**，功能边界需重新裁剪。
