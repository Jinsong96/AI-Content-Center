## 0. 一句话结论

**MAIN 的链路是通的、12 档是齐的、模型与参数是对的。但「篇幅」这个最核心的分级维度，目前不由档位规格决定，而由素材信息量决定。**
同时发现 1 个格式解析缺陷（已可复现）。这两点都会直接影响后端对接，需先拍板再改。

## 2. 发现一（P0）· 篇幅不按档位收敛，由素材信息量驱动

### 2.1 数据

| 档位 | 硬区间 | #1 词数 | #2 词数 | #3 词数 | 目标中点 |
|---|---|---|---|---|---|
| A1.1 | 60-90 | 69 | 67 | **111** (+21) | 75 |
| A1.2 | 90-120 | 84 | 97 | **135** (+15) | 105 |
| A1.3 | 120-160 | **85** (-35) | 113 | 166 | 140 |
| A2.1 | 160-200 | 147 | 176 | **237** (+37) | 180 |
| A2.2 | 200-250 | 177 | 221 | **312** (+62) | 225 |
| A2.3 | 250-300 | 209 | 254 | **340** (+40) | 275 |
| B1.1 | 300-380 | 388 | 330 | 342 | 340 |
| B1.2 | 380-450 | 392 | 369 | 407 | 415 |
| B1.3 | 450-550 | 448 | 462 | 450 | 500 |
| B2+.1 | 550-700 | 466 | 543 | **823** (+123) | 625 |
| B2+.2 | 700-900 | 584 | 600 | 781 | 800 |
| B2+.3 | 900-1200 | **646** (-254) | **648** (-252) | 940 | 1050 |

### 2.2 三个稳定规律（不是随机波动）

1. **短素材（4 条事实）→ 高段位系统性偏短。**
   B2+.3 两次跑出 **646 / 648 词**（差 2 词），目标 900–1200。**100% 可复现。**
2. **长素材（9 条事实）→ 低段位系统性超写。**
   A2.2 跑到 **312 词**（上限 250，超 25%）；A1.1 跑到 **111 词**（上限 90，超 23%）。
3. **梯度会逆序。**
   长素材下 `A2.3 (340) > B1.1 (342)` 基本持平，`B2+.1 (823) > B2+.2 (781)` **逆序** —— 高段位内部没拉开。

### 2.3 根因（已定位到代码）

`tools/dify_build_graphs.py` 里：

- `ruler(L)`（L112）把全篇词数换算成「每段多少词 / 约几句」，数学**是对的**。
  例：B2+.3 → 「全篇 8 段；每段约 112–150 词（约 5 句，平均句长约 24 词）」。
- 但实际生成只写到 **约 3.4 句/段**（648 ÷ 8 段 ≈ 81 词/段）。
- **段数是"结构约束"，模型严格遵守**（8 段就是 8 段）；
  **每段句数是"长度约束"，模型不遵守**。
- 同时 `gen_user` 里要求「每段至少引用 1 张事实卡；尽量让全部事实卡都被至少一段引用」。
  素材只有 4 条事实却要铺 8 段 × 112 词 → **内容不够，模型选择少写**（因为"事实一致性"是硬校验，宁可短也不编）。

**补充（提示词内部矛盾，需一并修）**：`gen_sys` 第 183 行写着
「**实测最容易犯的错是超写三成以上**」——这与实测（偏短）**方向完全相反**。
很可能是早期迭代留下的过期结论。而 B2+ 组第 146–148 行又写着
「实测本组系统性偏短…请按标称值 620 / 800 / 1050 写足」——**同一个提示词里两种相反引导并存**。

### 2.4 对后端对接的影响

> **素材长度 → FACT 事实条数 → 能写出的篇幅，是强耦合的。**
> 后端如果拿一句话标题直接送 MAIN，B2+.3 **必然不达标**。
> 建议在接口契约里加一条硬约束：**送 MAIN 的素材，英文正文不少于 8–12 条事实卡 / 约 300 词**，
> 否则应拒绝入队或降级只生成低段位。

## 3. 发现二（P1）· 模型输出格式漂移，生词表混进正文（可复现）

### 3.1 现象

长素材那一跑，**B1.1 / B1.2 / B1.3 三档的段落数都是 11**（规格是 6 段）：

```
B1_1 #7  flood — 洪水
B1_1 #8  basin — 蓄水池
B1_1 #9  barrier — 屏障
B1_1 #10 relocate — 迁移
B1_1 #11 investment — 投资
```

即：**模型把生词表当成了段落，追加到了正文数组末尾**，而不是放进 `words` 字段。
`B2P_1` 也出现 9 段（规格 8），但那一段是真正文（多写一段）。

### 3.2 跨跑次统计

| 跑次 | 段数不符的档位 |
|---|---|
| 短素材 #1 | 无 —— 12 档段数全部正确 |
| 短素材 #2 | 无 —— 12 档段数全部正确 |
| **长素材** | **B1_1 (11≠6)、B1_2 (11≠6)、B1_3 (11≠6)、B2P_1 (9≠8)** |

### 3.3 根因

`tools/dify_build_graphs.py` 的 `GEN_AGG_CODE`（L341）：

```js
const arr = (Array.isArray(o[k]) ? o[k] : []).map((p) => String(p || '').trim()).filter(Boolean);
paras[k] = arr;   // ← 直接信任模型数组长度，没有任何防御
```

聚合节点**只检查 "是不是数组"，不检查 "段数是否等于规格段数"**，
也不过滤 `word — 中文释义` 这种生词表行。
所以模型一漂移，脏数据就一路透传到 `paras_json` / `para_count` / `levels_meta`。

> ⚠️ **触发条件是"素材变长 → B1 组内容变多 → 输出格式漂移"**，
> 也就是说：**越用真实的长素材，越容易命中。** 上线后大概率会遇到。

### 3.4 对后端对接的影响

`paras_json` 的段数是**契约的一部分**（"三个子档段落级一一对应"靠它保证）。
现在它**不可信**。后端如果按 `paras_json` 做段落对齐或渲染，会拿到 11 段。

## 4. 发现三（P2）· 校验器文案不准确（但检测本身是对的）

`tests` → `validate()` 里「语言纯净度」这条：

```js
const zh = (String(article || '').match(/[\u4e00-\u9fff]/g) || []).length;
if (placeholders || zh > 5) fails.push('语言纯净度: 正文含中文 ' + zh + ' 字');
```

- 它检查的是 `body[key]`（= 纯正文，来自 `plain_json`），**检测逻辑正确** ——
  它确实抓到了"生词表混进正文数组"这个真问题。
- 但**报错文案说"正文含中文"，实际是"生词表混进了 paras 数组"**。
  实测三跑，**去掉生词表后正文中文均为 0 字**。
- 结论：**文案应改为「正文段落中疑似混入生词表/中文字符」，并把命中片段一并回传**，
  否则人工审核会被误导。

## 5. 已排除的怀疑（避免误判）

| 怀疑 | 实测结果 | 结论 |
|---|---|---|
| `max_tokens` 太小导致截断 | 9 个 LLM 节点均已确认：B2+ 给 12000，B1 给 6000，A2 给 4000，A1 给 2500 | ❌ 不是瓶颈 |
| 模型渠道不对 | 9 个节点全部为 `langgenius/siliconflow/siliconflow` + `deepseek-ai/DeepSeek-V4-Flash` | ✅ 正确 |
| `enable_thinking` 未生效 | 9 个节点全部 `enable_thinking: false` | ✅ 正确 |
| 素材被截断 | `facts_text` 全量透传（短 63 词 / 长 183 词，无截断） | ❌ 不是原因 |
| MAIN 拼装引入了额外问题 | 生成节点配置与 GEN 一致；差异仅在 `nodeClean` 引用改写与闸门语义 | 待单独复跑 GEN 对比 |

## 6. 修复方案（待拍板，尚未动手）

### 方案 A · 聚合端加防御（改动最小、收益最大）
在 `GEN_AGG_CODE` 里：
1. 按规格段数 `n` **截断或补齐** `paras[k]`；
2. 过滤匹配 `^[A-Za-z][A-Za-z' -]*\s*—\s*[\u4e00-\u9fff]` 的行（生词表误入）；
3. 段数不符时写入 `map_warn`，让后端能感知。
> 只需改一个 code 节点，不动提示词，风险最低。

### 方案 B · 生成端拆节点（根治，但工作量大）
把「一个大档一个 LLM 节点」拆成「一个子档一个 LLM 节点」（4 → 12 个）。
单节点只专注一篇，字数收敛会显著变好。
> 代价：节点数 +8，耗时与 token 上升，需重新压测。

### 方案 C · 提示词纠偏（立即能做，效果有限）
1. 删掉第 183 行「最容易犯的错是超写三成以上」这句**过期结论**；
2. 把「每段词数」提到与「段数」同等的硬约束地位，并给出**每段句数**的明确要求；
3. 素材事实卡不足时，允许模型展开背景知识（并标记为 `unused_facts` 之外），
   或明确"素材不足时优先保证下限、允许合理科普性扩写"。

### 建议顺序
**A（先止血） → C（同步纠偏） → B（如仍不达标再做）**。
