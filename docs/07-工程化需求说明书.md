## 1. 项目概述

### 1.1 产品定位

面向 K12 英语教研场景的 **AI 辅助内容生产平台**：从互联网热点 / 自有版权 / 公版书中采集英文素材，经敏感筛查、事实抽取、CEFR 分级改写（A2 / B1 / B2 三档）、人工逐段审核后，产出可发布的分级阅读文章，并配套封面、音频、阅读题。

### 1.2 核心价值主张

> **AI-assisted · Human-verified** —— AI 负责生产，人负责把关。每一篇发布的内容都必须经过人工逐段审核，AI 不直接产出可发布内容。

这条原则决定了整个系统的流程设计：**任何自动化环节都不能绕过人工审核节点**。

### 1.3 当前状态

| 层面 | 状态 |
|---|---|
| UI / 交互 / 权限模型 | ✅ 完整可用，16 个功能模块全部可跑 |
| Dify 生成链路 | ✅ 真跑（前端直连 Dify Cloud） |
| 封面生成 | ✅ 真跑（前端直连 SiliconFlow Kolors） |
| 素材抓取 / 原文抓取 | ⚠️ 依赖本地桥接层 + 本机 Chrome |
| 三层标签提取 | ⚠️ 依赖本地桥接层 |
| TTS 音频 | ⚠️ 依赖本地桥接层，音频文件存本地磁盘 |
| 数据持久化 | ❌ 100% 浏览器 localStorage，无服务端 |
| 鉴权 | ❌ 无，前端硬编码账号密码 |

### 1.4 工程化目标

1. 数据落到服务端数据库，多用户共享同一份数据
2. 所有第三方 API 调用收口到服务端，密钥不进前端
3. 素材抓取、标签提取、TTS 服务端化，不再依赖个人电脑
4. 真实鉴权 + 服务端权限校验
5. 前端工程化（构建化、模块化、可测试）

## 2. 核心概念与术语

| 术语 | 说明 |
|---|---|
| **Step** | 功能模块编号 0–15，共 16 个。前端路由与权限的基本单位 |
| **Level（档位）** | CEFR 分级 `A2` / `B1` / `B2`，一篇文章同时产出三档 |
| **Style（文风）** | 8 种：默认 / 海明威 / 朱自清 / 欧·亨利 / 马克·吐温 / 村上春树 / 鲁迅 / 莎士比亚 |
| **三层标签** | ① 内容标签（固定分类，如「世界/科学/文化」）② 自由标签（AI 提取约 5 个）③ 认知标签（全年龄/青少年向/成人向） |
| **事实卡（Fact）** | 从素材中抽取的事实陈述，是文章生成的素材基础；文章段落需与事实卡绑定 |
| **素材（Material）** | 入库的原始材料，含原文全文 |
| **文章（Article）** | 由素材生产的成品，含三档正文、段落、封面、音频、题目 |
| **敏感等级** | S0–S3，S3 及以上的素材在生产前被排除 |

### 3.3 关键设计约束（**请勿违反**）

1. **不绕过人工审核**：AI 产出的内容必须经人工逐段审核才能进入发布环节。这是产品原则，不是技术限制。
2. **生产者不自审**：教研老师（produce 角色）不能操作「逐段审核」（step 10），这是内控设计，不是 bug。
3. **绝不伪造内容**：抓取失败就如实标记降级，不许用 AI 编造的摘要冒充原文。（历史上曾踩过这个坑，见 `08` 文档）
4. **状态判断单一真源**：文章状态由 `artStatus()` 统一推导，不要在多处各写一套判断。

### 4.2 关键模块说明

#### 模块 0–1：素材采集

- 三种来源：**热点**（自动抓取）、**自有版权**（上传/录入）、**公版书**（内置语料）
- 热点抓取支持主题筛选，主题词表见 `agent_reach_bridge.py` 的 `THEME_KEYWORDS`
- 抓取结果需标记正文可信状态：`fulltext`（抓到全文）/ `summary`（仅摘要）/ `no_source`（无源）
- **抓取失败的降级策略需要产品确认**（见 `08` 文档第 5 章）

#### 模块 2：敏感排除

调用 Dify 事实抽取工作流，返回敏感等级与理由。判定逻辑：

```javascript
isExcludedStatus(status)  // 兼容 "exclude" | "excluded" | "block" | "reject"
```

⚠️ **重要**：Dify 工作流的「通过」与「排除」两条分支返回**不同的字段名**（见 6.2），工程化时应在 Dify 侧统一输出 schema。

#### 模块 3：三层标签

- 第一层内容分类为固定枚举，由服务端 `/api/tags/taxonomy` 下发（**词表单一真源，前端不内置副本**）
- 第二层自由标签由 AI 提取约 5 个
- 第三层认知标签：全年龄 / 青少年向 / 成人向

#### 模块 5–8：生产链路

事实抽取 → 分级标准 → 内容生成 → AI 校验，四步串在一条 Dify 链路上：

```
素材原文（截断 4800 字符）
   → [Dify 事实抽取] 事实卡 + 敏感等级
   → [Dify 内容生成] A2/B1/B2 三档 × 当前文风
   → 前端渲染 + 段落切分
```

#### 模块 10：逐段审核（三栏对照）

核心交互：左「档位切换条」+ 三栏网格（原文 / 段落 / 事实卡），逐段比对审核。

- 缺档时用空态卡占位，保持三栏网格结构不变
- 段落来源优先取 `article.paras[level]`，老数据回退到从 `article.articles[level]` 按 `\n{2,}` 切分

#### 模块 11：内容库

- 8 列列表：来源 / 状态 / 文章 ID / 生成老师 / 主题 / 生成时间 / 操作
- 6 张统计卡**同时是筛选器**（点击切换筛选）
- 文章详情抽屉：关闭 / 查看原文 / 人工审核
- 「查看原文」为独立三栏页（原素材全文 vs 三档文章）

```javascript
  facts: ["事实卡1", "事实卡2"],
  identity: {
    contentId: "内容 ID",
    tags: { /* 三层标签结构 */ }
  },
  coverDataUrl: "data:image/png;base64,...",  // ⚠️ 必须改为对象存储 URL
  coverPrompt: "英文视觉描述词",
  audio: { /* { "A2_us": "/audio/xxx.mp3", ... } */ },
  audioMeta: { /* TTS 元信息 */ },
  quiz: { /* 阅读题 */ },
  factMap: { /* 段落 ↔ 事实卡绑定 */ },
  unusedFacts: ["未使用的事实卡 ID"],
  createdAt: 1699999999999,
  createdByRole: "produce",             // 生成者角色
  reviewedBy: "审核老师",                // ⚠️ 改为审核人 user_id + 时间
  status: "待推送",                      // ⚠️ 冗余字段，实际状态由下方推导
  // 审核相关（后加）
  reviewResult: "approved" | "rejected" | undefined,
  published: false
}
```

**状态推导（唯一真源，请勿在别处重写）**：

```javascript
function artStatus(a){
  if(a.published) return "published";
  if(a.reviewResult === "rejected") return "rejected";
  return a.reviewedBy ? "approved" : "pending";
}
```

四种状态：`pending（待审核）` / `approved（已通过）` / `rejected（已驳回）` / `published（已发布）`

## 6. 接口契约

### 6.1 后端自研接口（10 个）

> **现成参考实现**：`output/backend/agent_reach_bridge.py`（Python 标准库 `http.server`，1967 行）。
> 这 10 个接口的输入输出、错误处理、降级逻辑**全部已实现且可运行**，可直接迁移到 FastAPI。

#### 统一约定

- Base URL：工程化后为同源 `/api`（当前为 `http://127.0.0.1:8787`）
- 全部返回 JSON，字段 `ok: boolean`
- CORS：当前 `Access-Control-Allow-Origin: *`，工程化同源后应移除
- **降级标识**：部分接口返回 `degraded: true` 表示「结果不完整」，前端据此提示用户，而非当作「没有数据」

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | 健康检查 |
| GET | `/api/trends` | 热点榜单 |
| GET | `/api/scan` | 按 URL 抓取 |
| GET | `/api/tags/taxonomy` | 标签词表（单一真源） |
| POST | `/api/tags/extract` | 三层标签提取 |
| POST | `/api/tts` | 单条 TTS |
| POST | `/api/tts/batch` | 批量 TTS |
| GET | `/api/library` | 文章列表 |
| POST | `/api/library` | 文章入库（upsert） |
| GET | `/api/source-health` | 信源健康度 |
| GET | `/api/errors` | 近期错误（诊断用） |
| GET | `/audio/{file}` | 静态音频（⚠️ 应改对象存储） |

### 6.2 外部依赖：Dify（3 个工作流）

**调用方式**：`POST https://api.dify.ai/v1/workflows/run`

### 6.3 外部依赖：SiliconFlow

| 能力 | 模型 | 用途 |

**⚠️ 三个必须记住的约束**：

| `ops` | 运营老师 | `ops_zhao` | 发布与运营 |

### 7.2 权限矩阵（RBAC 输入）

权限唯一真源为 `ROLE_OPS`，值即 step 编号 0–15：

| 角色 | 可操作 step |
|---|---|
| `source`（市场老师） | 0, 1, 2, 3, 4 |
| `produce`（教研老师） | 0–9, **11**（**不含 10**，生产者不自审） |
| `review`（审核老师） | 全部 0–15 |
| `ops`（运营老师） | 12, 13, 14, 15 |

> ⚠️ `STEP_OWNER` 数组仅用于侧边栏视觉标注（owner 色点 / 只读提示），**不作为权限判断依据**。

### 7.3 工程化要求

1. 真实登录：账号密码存库（bcrypt），返回 JWT
2. **服务端二次校验权限**，不能只靠前端 `canOperate()`（改一行 JS 就能越权）
3. 数据归属：素材的 `collectedBy`、文章的 `createdByRole` 改为真实 `user_id` 外键

## 8. 非功能需求

| 类别 | 要求 |
|---|---|
| **安全** | 密钥全部服务端化；鉴权 + 服务端权限校验；敏感内容 S3+ 强制拦截 |
| **性能** | 热点抓取 < 15s（带 5 分钟缓存）；事实抽取 5–10s；文章生成 20–40s；TTS 单条 < 90s |
| **可靠性** | 第三方 API 失败必须**显式降级并告知用户**，不允许静默吞掉错误或伪造内容 |
| **可观测** | 保留现有 `/api/source-health`（信源健康度）与 `/api/errors`（错误环形缓冲）能力，接集中日志 |
| **存储** | 封面图、音频、素材原文全文走对象存储 + CDN，库里只存 URL |
| **配额** | Dify Cloud 与 SiliconFlow 均有额度限制，需加调用计数与限流 |
| **并发** | 素材抓取与 TTS 批量需队列化，避免用户多点几次打满配额 |

## 附录 A：常见误区（来自实际踩坑记录）

1. **别按函数名推断它对应哪个 step**。历史遗留导致 `s12` 实际是「逐段审核」，`s9` 是「段落校对」，`s4` 是「事实抽取」。**一律以路由数组下标为准**。
2. **改 step 相关逻辑时，六处必须同步**：`STAGES` / `stepLabel` / 路由数组 / `SECTIONS` / `STEP_OWNER` / `ROLE_OPS`。漏一处就错位白屏。
3. **localStorage 种子数据改了「看不见」**：预填充数据落盘后，「有缓存直接返回」的逻辑会让新数据永不生效。改 schema 必须做版本迁移或旧数据检测清除。
4. **Dify 输出字段别照抄现有代码**，先用真实参数打一次，把 outputs 全量打印出来再写解析。
5. **状态字符串一律写成兼容集合**，不要只写一个值。
