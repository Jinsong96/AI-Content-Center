## 1. 分级体系（全链路唯一标准）

**12 子档，4 个大档**：

```
A1 入门    A1.1  A1.2  A1.3
A2 初级    A2.1  A2.2  A2.3
B1 中级    B1.1  B1.2  B1.3
B2+ 中高级 B2+.1 B2+.2 B2+.3
```

### ⚠️ 两套键名，必须做归一化（最容易踩的坑）

| 出现位置 | 格式 | 例子 |
|---|---|---|
| `articles_json` / `quiz_json.levels` / `levels_meta` / `para_count` / `words_json` 的 **key** | **下划线式** | `A1_1`、`B2P_3` |
| `validation_json.results[].level`、`level`、`level_big` | **点式** | `A1.1`、`B2+.3` |

后端/前端都需要一层 `A1_1 ↔ A1.1`、`B2P_1 ↔ B2+.1` 的转换。

### 兼容别名（过渡期仍在，不要依赖）

`article_a2` / `article_b1` / `article_b2`、`paras_a2/b1/b2` 分别取该大档**中间子档**
（`A2.2` / `B1.2` / `B2+.2`）。**新代码请直接用 `articles_json`。**

### 3.2 POST（GET 会 404，属正常）

**`POST /api/dify/workflows/run`** —— 后端代理到 Dify（**推荐走这条，不要浏览器直连**）

```json
{ "wf": "fact | gen | main",
  "inputs": { "material": "..." },
  "response_mode": "blocking | streaming",
  "user": "frontend-demo" }
```

实测：`wf=fact` → HTTP 200 / **23.9s** / `level=A2.2`。
返回体是 Dify 原始响应**加一层 `_proxy_ms`**：`{task_id, workflow_run_id, data:{status, outputs}, _proxy_ms}`。

> ⚠️ **两个必须知道的限制**
> 1. 代理内部 **`timeout=180s`**，而 GEN 实测最长 **221s** → **GEN 走代理会被截断**。
>    修法：把 `_proxy_post` 的 timeout 提到 300s 以上（`agent_reach_bridge.py` 代理分支）。
> 2. `response_mode` 默认 `"blocking"`，而 Dify 网关有 **约 120s 硬超时** →
>    MAIN（103s+）和 GEN 走 blocking 有 504 风险。**长工作流必须显式传 `streaming`。**

**`POST /api/tts/batch`** —— 批量语音

```json
{ "articles": {"A1_1": "text...", "B2P_1": "text..."}, "accents": ["us","uk"] }
```

实测：HTTP 200 / 5.9s / `succeeded=2 failed=0`，返回 `audio[档位][口音]=url`。
键支持下划线式（`A1_1`）与点式（`A1.1`）混用。模型 `FunAudioLLM/CosyVoice2-0.5B`。

**`POST /api/tags/extract`** —— `{"material":"...","title":"..."}` → 三层标签
**`POST /api/library`** —— 文章对象入库（`{"ok":true,"id":...,"library_count":N}`）
**`POST /api/sf/chat/completions`** / **`/api/sf/images/generations`** —— SiliconFlow 透传代理

## 4. MAIN / GEN 输出契约（30 个字段，实测）

```
articles_json   12 档全文        {"A1_1":"# 标题\n\n...", ..., "B2P_3":"..."}
paras_json      12 档分段数组
query_json      12 档 × 3 题      {"levels":{"A1_1":[{...},{...},{...}], ...}, "guide":{"B2P_3":"中文背景导读"}}
words_json      12 档词表        {"A1_1":["cool — 使凉爽", ...], ...}
levels_meta     12 档元信息      {"A1_1":{"display":"A1.1","big":"A1","words":74,"paras":4}, ...}
validation_json 逐档校验明细     {"results":[{"level":"B1.1","score":6,"pass":false,"checks":[...]}]}
validation_pass / validation_score   汇总（实测 83–91 / 96）
level / level_big   分级结果（实测 A2.2 / A2）
title · summary · angle · facts_json · facts_text · facts_raw
identity_json · fact_map · fact_count · unused_facts · map_warn · para_count
sens_level · sens_reason           敏感分级（S3 = 正常）
article_a2/b1/b2 · paras_a2/b1/b2  兼容别名（取中间子档）
```

### 题目四类（`type` 字段）

| type | 含义 |
|---|---|
| `language` | 语言基础 |
| `text` | 文本理解 |
| `logic` | 逻辑推断 |
| `cognitive` | 认知迁移 |

配比随档位递进（A1 以 `language`/`text` 为主 → B2+ 以 `logic`/`cognitive` 为主），**逐档精确匹配规格**。

### `guide`（中文背景导读）

**只有 `B2P_3` 一档有**（B2+ 大档才显示）。前端 `guideCardHTML()` 负责渲染。

## 5. 已知坑（都是实测踩出来的）

| # | 坑 | 现象 | 处理 |
|---|---|---|---|
| 1 | Dify `select` 入参**不能传空字符串** | `level=""` → `level in input form must be one of the following: [...]`，且**工作流秒退** | `required=false` 也要**整个省略该键**，不要传 `""` |
| 2 | Dify 网关 **blocking ~120s 硬超时** | 长工作流 504 | 用 `response_mode: "streaming"` 走 SSE |
| 3 | api.dify.ai **偶发 Cloudflare 403 `code 1010`** | 看起来像密钥失效 | **不是失效，重试即可**（实测换 UA 无关） |
| 4 | Dify 控制台 **CSRF cookie 短时失效** | 控制台 API 全部 401 `Invalid Authorization token` | 刷新一下 Dify 页面，`__Host-csrf_token` 会重新签发 |
| 5 | 改 Dify 图**推完 hash 不变** | 以为改好了，其实没生效 | 推送后必须比对 `draft.hash` 有没有变 |
| 6 | 知识库**跨语言检索 0 命中** | 英文素材 query 打中文标准文档 → 静默返回空数组 | 前面挂一个 code 节点输出**固定中文检索意图词** |
| 7 | **`paras_json` 段数不可信**：模型会把**生词表当成段落**追加到正文数组末尾 | 长素材实测 B1.1/B1.2/B1.3 段数 **11**（规格 6），多出来的正是 `flood — 洪水` 这类生词表行；`B2P_1` 也是 9≠8 | 见第 6 节 P0-3；**后端不要盲信 `paras_json.length`**，以 `levels_meta[k].paras` 的规格值为准 |
| 8 | **篇幅由素材信息量驱动，不由档位规格驱动** | 同一素材长度下 B2+.3 两次跑出 **646 / 648 词**（目标 900–1200）；素材换成 374 词后 B2+.3 到 940 词，但 A2.2 反冲到 **312 词**（上限 250） | 见第 6 节 P0-4。**送 MAIN 的素材必须有足够事实量** |
